# M7 设计大纲 —— 超级个人工作台（第一阶段）

> 状态：草案 v0，等用户拍板。落地前所有数字、字段、按钮位置都可改。
> 起源：从"资源管理工作台"扩展为"一起工作开始的入口"。第一阶段聚焦三个痛点：
> 1. todo 散落各处容易丢失，需要固定入口 + 关联项目
> 2. 终端窗口按项目管理（内嵌终端）
> 3. 资源"只能看不能用"，缺打开/操作联动

---

## 0. 设计原则（沿用并扩展）

- **不搬家**：真实文件不动；todo 是新建数据，天然在工作台内
- **聚合而非替代**：终端内嵌 ≠ 替代 iTerm，是"项目上下文里的快速终端"
- **每里程碑可用**：四个子任务独立交付，做完一个就有一个能用的东西
- **数据先行**：todo 的表结构先想清楚，避免后期 migration 翻车

---

## 1. M7 总目标与里程碑划分

```
M7-1  资源打开/操作        前端补齐 ref_open 调用 + 右键菜单（0.5d）
M7-2  TodoList + 关联      新表 todo + todo_ref_link，含项目/资源挂载（2d）
M7-3  Dashboard 首页       工作台首页：今日 todo + 最近资源 + 空间入口（1.5d）
```

**关键依赖**：M7-1 独立；M7-2 独立；M7-3 依赖 1+2；M7-4 独立（但建议放最后，工程量最大）。

## 3. M7-2 TodoList

### 数据模型（新增 2 张表）

```sql
-- 0006_todo.sql
CREATE TABLE todo (
    id           TEXT PRIMARY KEY,
    title        TEXT NOT NULL,
    note         TEXT,                        -- 备注/思路记录
    status       TEXT CHECK (status IN ('pending','doing','done','cancelled')) NOT NULL DEFAULT 'pending',
    space_id     TEXT REFERENCES space(id) ON DELETE SET NULL,  -- 关联项目（可空 = 全局 todo）
    priority     INTEGER NOT NULL DEFAULT 0,  -- 0 普通 1 重要 2 紧急
    due_at       INTEGER,                     -- 截止时间（可空）
    done_at      INTEGER,
    created_at   INTEGER NOT NULL,
    updated_at   INTEGER NOT NULL,
    sort_order   INTEGER NOT NULL DEFAULT 0   -- 手动排序
);
CREATE INDEX idx_todo_status ON todo(status);
CREATE INDEX idx_todo_space ON todo(space_id);
CREATE INDEX idx_todo_due   ON todo(due_at);

-- todo 与资源的多对多挂载
CREATE TABLE todo_ref_link (
    todo_id   TEXT NOT NULL REFERENCES todo(id) ON DELETE CASCADE,
    ref_id    TEXT NOT NULL REFERENCES resource_reference(id) ON DELETE CASCADE,
    created_at INTEGER NOT NULL,
    PRIMARY KEY (todo_id, ref_id)
);
```

### 关键决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 项目关联粒度 | 挂到 `space`（不挂 collection） | 项目=空间是用户脑里的模型，collection 太细 |
| 可空 space_id | 允许 | "回邮件"这种全局 todo 不属于任何项目 |
| 资源挂载 | 多对多 link 表 | 一个 todo 挂多个资源；一个资源被多个 todo 挂 |
| 状态机 | pending/doing/done/cancelled | 简单四态，先不上 in_review 之类 |
| 优先级 | 0/1/2 | 不做 ABC 五级，过度设计 |
| 子任务 | **不支持** | 第一版保持平铺，复杂了就用 note |

### 后端命令

```
todo_list(filter: {space_id?, status?, due_before?})  -> Vec<Todo>
todo_get(id)                                          -> TodoWithRefs
todo_create(input)                                    -> Todo
todo_update(id, patch)                                -> Todo
todo_set_status(id, status)                           -> Todo
todo_delete(id)                                       -> ()
todo_link_ref(todo_id, ref_id)                        -> ()
todo_unlink_ref(todo_id, ref_id)                      -> ()
```

### 前端入口（三处）

1. **左侧导航新增"待办"**：全局 todo 列表，可按空间筛选
2. **空间详情页加 tab**：进入某空间 → 看到"概览 / 资源集 / 待办"三个 tab
3. **资源详情面板**：显示"被哪些 todo 引用"，可一键"挂到 todo"

### 快速记录（核心场景）

全局快捷键（后续）：`Cmd+Shift+T` 弹出快速输入框 → 默认进"收件箱"（space_id=null）→ 事后再分配项目。
**第一版只做应用内快速记录按钮**，全局快捷键留到 M8。

## 5. M7-4 内嵌终端

### 技术选型

- 前端：**xterm.js** + `@xterm/addon-fit` + `@xterm/addon-web-links`
- 后端：**`portable-pty`** crate（跨平台 PTY，我们只需要 macOS 但保留可移植性）
- 通信：Tauri Channel（比 invoke 流式更合适）

### 会话模型

```rust
struct PtySession {
    id: String,
    space_id: Option<String>,  // 关联空间；null = 全局终端
    cwd: PathBuf,               // 初始目录 = 空间根目录
    shell: String,              // 默认 $SHELL，fallback /bin/zsh
    child: Box<dyn Child>,
    master: Box<dyn MasterPty>,
}
```

### 前端集成

```
空间详情页  →  新增"终端" tab
                ↓
        ┌───────────────────────┐
        │ [tab1] [tab2] [+]     │  ← 每个 tab 一个 PtySession
        ├───────────────────────┤
        │                       │
        │   xterm.js 画布       │
        │                       │
        └───────────────────────┘
```

### 边界（明确不做）

- ❌ 跨窗口拖出终端
- ❌ 分屏（先单 tab 一个终端）
- ❌ 会话持久化（关了就没了，重启应用不恢复）
- ❌ SSH 管理、tmux 集成（这些是 M8+ 的事）
- ❌ 全局悬浮终端（先长在项目里）

### 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| portable-pty 在 macOS arm64 兼容性 | 高 | 先做个 5 分钟 spike 验证 |
| xterm.js 与 antd 样式冲突 | 低 | 已有成熟方案，CSS 隔离 |
| 会话泄漏（前端关了后端没杀） | 中 | Drop trait + 心跳检测 |
