# 资源管理工作台需求说明书（第一版）

## 1. 背景与问题

现有文件系统以目录和文件为中心，适合保存资料，却不能稳定表达资料服务于什么事项、彼此如何关联、应从何处获取。工作产品、客户项目、个人生活、代码仓库、文档和数据往往分布在多个目录或多个服务中；只依赖目录层级，会带来重复存放、迁移成本和上下文缺失。

本产品建立一层独立于文件系统的管理元数据。用户主动建立空间、资源集和资源引用，再把真实文件或外部服务连接进来。文件可以移动、存储源可以替换，但管理关系保持稳定。

## 2. 产品定位

一个以“连接资源”为核心的个人资源管理工作台。

- 管理层：维护空间、资源集、资源类型、说明、标签和关联关系。
- 存储层：保存真实资源；第一期默认使用本地文件系统。
- 连接层：用资源引用将管理层连接到本地目录、文件、Git 仓库、云存储或其他服务。

产品不是新的网盘、Git 托管或文件管理器；它是这些资源之上的统一组织与检索入口。

## 3. 目标与范围

### 3.1 第一阶段目标

- 以“空间 → 资源集 → 资源类型”组织管理元数据。
- 手动创建资源集，不从目录结构自动推断产品、项目或生活事项。
- 将本地目录、文件和 Git 仓库作为资源引用关联到资源集。
- 提供资源分类、说明、标签、状态和访问限制等管理属性。
- 为 Git、云存储、对象存储等后续存储源预留统一接入模型。
- 保持本地优先：不复制、不移动原始文件，默认不上传内容。

### 3.2 非目标

- 第一阶段不实现完整的项目管理、需求管理、代码托管、云盘同步或部署流水线。
- 第一阶段不自动替用户判定一个目录究竟是产品、项目或知识库。
- 第一阶段不将“已交付”“已归档”作为资源类型；它们是资源的管理属性。

## 4. 核心概念与层级

| 层级 | 定义 | 示例 |
| --- | --- | --- |
| 空间（Space） | 顶层管理边界，用于区分生活领域、权限和关注范围。 | 工作空间、生活空间 |
| 资源集（Resource Collection） | 围绕一个主题、项目、产品、活动或目标组织的一组资源。 | 项目 A、产品 B、去云南旅游 |
| 资源类型（Resource Type） | 资源的主用途分类，用于筛选、提示存储策略和展示方式。 | 代码库、文档、数据、制品、工具、媒体素材 |
| 资源引用（Resource Reference） | 指向真实资源的管理记录，不保存资源本体。 | 本地目录、文件、Git 仓库地址、云盘链接 |
| 存储源（Storage Source） | 真实资源所在的位置及其访问方式。 | 本地文件系统、Git、云存储、对象存储 |

关系如下：

```text
空间
└── 资源集
    └── 资源引用（带资源类型与管理属性）
        └── 存储源中的真实文件、目录、仓库或链接
```

一个资源集可以关联多个资源引用；同一个资源引用可在后续扩展为被多个资源集复用。资源集的名称和用途由用户定义，不硬编码“产品”“项目”“旅行”等业务类型。

## 5. 资源类型与识别规则

资源类型回答的是“这个资源主要用来做什么”，不是文件格式，也不是其当前状态。

| 类型 | 识别标准 | 常见示例 | 推荐的后续存储源 |
| --- | --- | --- |
| 代码库 | 主要用于开发、构建或维护软件；一个完整 Git 仓库视为一个代码资源。 | Git 仓库、源码目录、基础设施代码 | 本地文件系统、Git 托管 |
| 文档 | 主要由人阅读、沟通、确认或留存。 | 需求、方案、合同、会议纪要、旅行攻略 | 本地文件系统、云文档、云盘 |
| 数据 | 主要由程序导入、分析、恢复或计算。 | CSV、数据库备份、训练数据、配置数据 | 本地文件系统、对象存储、数据库 |
| 制品 | 构建、打包、发布或交付后形成的结果。 | 安装包、镜像、压缩发布包、导出报告 | 本地文件系统、制品库、对象存储 |
| 工具 | 用于操作、生成或维护其他资源的软件、脚本或运行环境。 | 通用脚本、命令行工具、容器定义 | 本地文件系统、Git 托管 |
| 媒体素材 | 主要用于视觉、音频、视频或创作表达。 | 图片、视频、音频、设计源文件 | 本地文件系统、云存储、对象存储 |

“已交付”“已归档”“客户受限”“敏感”等是管理属性。例如，一个已交付的方案仍是文档，一个归档的数据库备份仍是数据。

## 6. 功能需求

### 6.0 资源落地与托管方式

资源引用按来源分为两种，二者必须在界面和数据模型中明确区分：

| 方式 | 适用场景 | 文件位置 | 系统责任 |
| --- | --- | --- | --- |
| 外部引用 | 用户已有的目录、文件、仓库或云端资料。 | 保持原位置。 | 只保存定位、分类和管理关系，不改变原始资源。 |
| 系统托管 | 由工作台创建，或由用户选择“导入并托管”的资源。 | 放入该存储源约定的稳定目录。 | 负责创建、导入、重命名、迁移提示和处置。 |

系统托管的目的不是把所有资料集中搬运，而是保证即使脱离工作台，用户仍可按普通文件系统找到资源。管理层只是增强入口，不能成为资源唯一的定位方式。

对于默认的本地文件系统存储源，系统托管资源采用按资源类型划分的固定根目录；建议目录为：

```text
资源根目录/
├── Code/          # 完整代码仓库
├── Documents/     # 面向人阅读、沟通与确认的文档
├── Data/          # 面向程序处理、分析与恢复的数据
├── Artifacts/     # 构建、发布、交付产生的制品
├── Tools/         # 工具、脚本与运行环境
└── Media/         # 图片、音频、视频和设计素材
```

归档是管理状态，不另立为资源本体类型；需要进行物理冷存时，可在每个类型根目录下设置 `Archive/`，但资源仍保留其原始类型，例如 `Documents/Archive/` 或 `Data/Archive/`。

落地规则：

- 代码库以完整仓库为单位放在 `Code/` 下，不拆分仓库内的文档、配置或脚本。
- 系统创建或导入时，先由用户选择资源类型；系统据此建议目标目录，用户可确认或调整名称。
- 导入并托管是一次明确的复制或移动操作，必须展示来源与目标；默认不对已有资源做自动搬迁。
- 资源集不是物理目录层级的强制来源。一个“项目 A”可以关联 `Code/`、`Documents/`、`Artifacts/` 等多个根目录中的资源。
- 若用户在系统外移动或重命名托管资源，工作台应提示引用失效并提供重新定位，而不擅自重建文件。

### 6.1 空间管理

- 用户可以创建、编辑、归档空间。
- 空间至少包含名称、说明、颜色或图标、创建时间和状态。
- 默认预置“工作空间”和“生活空间”，可按需新增其他空间。
- 空间用于隔离浏览范围和未来的权限、检索范围。

### 6.2 资源集管理

- 用户可以在一个空间下创建资源集。
- 资源集至少包含名称、简述、状态、标签和创建时间。
- 资源集可使用自定义类型或模板，但系统不强制其必须是产品或项目。
- 用户可将资源集归档，而不影响其已关联的原始资源。
- 资源集详情页应按资源类型聚合显示已关联资源。

### 6.3 资源引用管理

- 用户可手动创建资源引用，并指定资源类型、名称、说明和所属资源集。
- 用户可从本地目录浏览器选择文件或目录作为资源引用目标。
- 用户可选择“仅关联现有资源”或“导入并托管资源”；后者必须落入与资源类型对应的固定目录。
- 对“仅关联”的资源，系统保存路径、资源类型、显示名称及必要识别信息，且不复制、不移动原文件；对“导入并托管”的资源，系统在用户确认后执行明确的复制或移动。
- 对 Git 仓库，可保存本地仓库路径或远程仓库地址，并预留分支、默认分支和最近同步状态字段。
- 用户可为资源引用添加标签、备注、敏感级别、生命周期、是否纳入检索等属性。

### 6.4 本地文件系统存储源

- 第一阶段内置且默认启用“本地文件系统”存储源。
- 支持选择文件或目录，展示名称、路径、基础类型和最近修改时间。
- 本地浏览仅用于选择和打开资源；目录层级不作为业务事实来源。
- 默认排除或提示敏感路径、密钥文件、日志和大型缓存目录；是否纳入检索由用户明确控制。

### 6.5 存储源扩展模型

- 存储源应具备名称、种类、连接状态、认证配置引用和能力说明。
- 第一阶段以本地文件系统为唯一实际接入源。
- 后续可按需增加 Git、云存储、对象存储、数据库或网页链接等连接器。
- 连接器差异由存储源适配层处理，上层的空间、资源集和资源引用模型保持稳定。

### 6.6 管理属性与检索

- 支持自由标签，以及生命周期、保密级别、检索权限等受控标签。
- 常规生命周期建议包含：活跃、暂存、已交付、已归档。
- 保密级别建议包含：公开、内部、客户受限、敏感。
- 支持按空间、资源集、资源类型、标签、状态和存储源筛选。
- 后续智能检索应以“用户授权的资源引用”为边界，而不是扫描整台电脑。

### 6.7 生命周期结束管理

资源的结束处置分为三个清晰级别，系统必须在界面、权限与操作记录上明确区分：

| 级别 | 含义 | 对原始文件的影响 | 可恢复性 |
| --- | --- | --- | --- |
| 归档 | 管理层逻辑归档，不再默认出现在日常工作视图中。 | 不移动、不删除原始文件。 | 可在管理层恢复；也可继续选择删除或销毁。 |
| 删除 | 请求存储源执行其支持的“可恢复删除”；同时将资源引用标记为已删除。 | 本地文件系统中为移入系统回收站；云端则由连接器执行该服务提供的软删除、回收站或保留策略。 | 取决于存储源；仅在该存储源明确支持时可恢复。 |
| 销毁 | 对原始文件或目录执行直接删除，作为最终处置。 | 文件从存储源永久移除。 | 不可恢复；操作前必须二次确认。 |

规则：

- 归档只改变管理层状态，因此不能被当作物理清理。
- 删除与销毁是对原始资源的写操作；第一阶段默认只对本地文件系统实现，其他存储源需由各自连接器明确声明支持的处置能力。
- 删除前应展示目标、影响范围、当前存储源及实际恢复方式；如果存储源不支持回收站、软删除或保留期，系统不得把该操作标为“删除”，而应提示用户只能归档或执行不可恢复销毁。
- 销毁前应展示目标、影响范围和“不可恢复”提示，并要求二次确认。
- 对目录执行删除或销毁时，必须先列出或统计其包含的资源；默认不允许通过模糊搜索结果批量销毁。
- 系统应记录处置时间、操作者、处置级别与原始定位信息；销毁记录保留为审计元数据，但不保留文件内容。

### 6.8 设置中心

系统需要提供独立的设置中心，作为管理层与真实存储环境之间的控制面。设置应分为以下四类：

| 设置项 | 说明 | 第一阶段要求 |
| --- | --- | --- |
| 系统资源根目录 | 系统托管资源在本地文件系统中的总根目录；其下按 `Code`、`Documents`、`Data`、`Artifacts`、`Tools`、`Media` 建立固定分类目录。 | 可查看、首次初始化、修改；修改前展示迁移影响与用户选择。 |
| 系统监控目录 | 可由系统观察变化、辅助发现资源失效或提示新资源的本地目录范围。 | 可添加、移除、暂停监控；默认不等于整台电脑。 |
| 存储源维护 | 管理本地文件系统及未来 Git、云存储、对象存储等连接器的名称、连接状态、根路径、能力与认证引用。 | 本地文件系统可用；其他类型先保留模型与配置入口。 |
| 默认查看程序 | 为资源类型设置“打开”时使用的默认程序或策略。 | 支持使用系统默认程序；可为代码库、文档、数据、制品、工具、媒体素材分别覆盖。 |

补充规则：

- 资源根目录与监控目录是不同概念。资源根目录用于系统托管资源的落地；监控目录用于观察已有资源，可以包含也可以不包含资源根目录。
- 修改资源根目录不得静默搬迁文件。系统必须先说明：仅修改未来新资源的默认位置、迁移已有托管资源，或取消修改；实际迁移必须逐项确认并记录结果。
- 监控仅产生“发现或失效提示”，不应自动创建业务资源集、自动分类或自动上传内容。
- 存储源维护页需要展示其可用能力，尤其是读取、创建、可恢复删除、永久销毁和打开链接；不支持的操作不得显示为可执行按钮。
- 默认查看程序是本地客户端偏好，不应写入资源本体；资源可单次选择其他程序打开。

### 6.9 资源收件箱

资源收件箱用于承接系统监控目录中新出现或发生重要变化的资源。它是“待人工归类”的缓冲区，而不是自动分类器。

#### 收件箱流程

1. 监听目录发现一个新文件或目录后，系统创建一条“收件箱条目”，记录其发现时间、来源路径、基础文件信息和监控目录。
2. 系统向用户提示收到新资源；提示应合并同一时间段内的多条事件，避免逐文件打扰。
3. 用户在收件箱中查看、预览或打开该条目。
4. 用户为其指定所属空间、资源集和资源类型，并选择后续处理方式。
5. 处理完成后，系统创建或更新正式资源引用，收件箱条目转为“已处理”。

#### 收件箱的处理方式

| 处理方式 | 结果 |
| --- | --- |
| 仅关联 | 保持文件在监控目录原位置，创建正式资源引用并关联到用户指定的空间、资源集与类型。 |
| 导入并托管 | 经用户确认，将文件复制或移动到资源根目录下对应类型的固定位置，再创建正式资源引用。 |
| 暂后处理 | 保留在收件箱，可加备注、截止时间或提醒。 |
| 忽略 | 不创建正式资源引用；可选择只忽略本次，或为同类规则静默忽略。 |
| 归档候选 | 将其作为待归档资源处理；仅对已明确关联的资源执行后续归档。 |

#### 收件箱条目字段

| 字段 | 说明 |
| --- | --- |
| 发现信息 | 发现时间、监控目录、原始路径、创建或修改事件。 |
| 基础信息 | 文件或目录名称、大小、修改时间、扩展名、可选预览。 |
| 建议信息 | 基于路径、扩展名或 Git 特征给出的类型建议；仅供用户参考。 |
| 处理状态 | 待处理、暂后处理、已关联、已忽略、已失效。 |
| 归属信息 | 用户确认后的空间、资源集、资源类型与处理方式。 |

#### 监听与提示规则

- 只监听用户在设置中心明确添加的目录；默认不监听整台电脑。
- 监听目录中的新资源先进入收件箱，不自动创建空间、资源集或正式资源引用。
- 对大批量复制、解压、构建和同步造成的连续变化，应按时间窗口聚合为一条或一组通知。
- 应提供过滤规则，至少支持忽略隐藏文件、临时文件、系统缓存、构建目录、日志和用户指定的名称或扩展名。
- 对可能包含密钥、凭据或敏感内容的文件，默认仅显示文件名和风险提示，不自动提取内容或纳入智能检索。
- 若已存在相同路径的正式资源引用，不重复生成收件箱条目；若资源被移动、重命名或删除，则提示“引用可能失效”，而非视作全新资源。
- 收件箱条目只保存发现记录，不等同于对文件拥有管理权；只有用户选择“导入并托管”后，系统才可改变物理位置。

## 7. 关键使用流程

### 7.1 新建一个工作项目

1. 在“工作空间”中新建资源集，例如“项目 A”。
2. 填写项目简述和可选标签。
3. 新建资源引用，选择“代码库”，从本地选择完整 Git 仓库。
4. 新建资源引用，选择“文档”，关联需求、方案或客户资料目录。
5. 新建资源引用，选择“制品”，关联发布包或交付目录。
6. 在资源集详情中按类型查看全部上下文。

### 7.2 新建一个生活事项

1. 在“生活空间”中新建资源集，例如“去云南旅游”。
2. 关联攻略文档、预算数据、照片素材和预订链接。
3. 用“文档”“数据”“媒体素材”等资源类型组织，而不是另造一套生活目录规则。

### 7.3 替换存储位置

1. 用户将某份文档从本地迁至云存储。
2. 更新该资源引用的存储源和定位信息。
3. 资源集、标签、说明和关联关系保持不变。

## 8. 数据模型（第一阶段）

| 对象 | 核心字段 |
| --- | --- |
| Space | id、名称、说明、状态、创建时间 |
| ResourceCollection | id、spaceId、名称、简述、标签、状态、创建时间 |
| ResourceReference | id、collectionId、名称、资源类型、sourceId、定位信息、托管方式、说明、标签、生命周期、保密级别、是否可检索、处置状态 |
| StorageSource | id、名称、种类、是否默认、连接配置引用、状态、处置能力 |
| SystemSettings | 资源根目录、监控目录列表、资源类型默认查看程序、存储源默认项 |
| InboxItem | id、监控目录、原始路径、发现信息、基础信息、建议类型、处理状态、归属信息、忽略规则引用 |

`定位信息` 在本地文件系统中为路径；在 Git 中为仓库地址或本地仓库路径；在云存储中为提供商对象标识或共享链接。`托管方式` 区分外部引用和系统托管。认证信息不直接存入资源记录，应由密码管理器或系统安全存储保管，管理层只保存引用或说明。

`处置能力` 用于声明该存储源是否支持：逻辑归档、可恢复删除、不可恢复销毁、回收站恢复、保留期查询。管理层基于能力决定可显示的操作，而不将本地文件系统的回收站行为套用到所有云端存储源。

## 9. 约束与原则

- 管理层优先：界面中的产品、项目或生活事项由用户创建，不由目录扫描自动生成。
- 原始资源优先：系统默认不重命名、不移动、不复制原始文件。
- 文件可寻址：系统托管资源必须遵循按类型划分的固定物理目录；即使没有工作台数据，用户仍可从文件系统理解并找到资源。
- 本地优先：第一阶段的数据和索引保存在本机。
- 显式授权：仅用户明确关联或允许索引的资源可进入搜索和后续智能问答。
- 保留完整性：代码资源以完整仓库为单位，仓库内的说明文件不强行拆到外部文档库。
- 可演进：新增存储源不应改变既有空间、资源集和资源引用的语义。
- 安全处置：归档、删除、销毁必须是三个独立动作；销毁不得提供无确认的快捷操作。

## 10. 验收标准

- 用户可创建工作空间、生活空间及自定义空间。
- 用户可在任一空间中创建资源集，并看到资源集内按资源类型分组的资源。
- 用户可从本地文件系统选择文件或目录，并以资源引用方式关联到资源集。
- 用户可将新建或导入并托管的资源落入 `Code`、`Documents`、`Data`、`Artifacts`、`Tools` 或 `Media` 对应的固定目录。
- 系统不会因建立关联而移动、复制或修改原始文件。
- 对“导入并托管”的资源，系统会在执行前清晰展示复制或移动目标；对“仅关联”的资源，不改动原文件。
- 用户可为资源设置类型、说明、标签、生命周期和保密级别。
- 用户可按类型、状态和标签筛选资源。
- 资源引用模型包含存储源字段，且本地文件系统作为默认实现可用。
- 未明确授权的目录和敏感资源不会被默认纳入检索。
- 归档资源可从管理层恢复，且原始文件不受影响。
- 本地文件系统的删除操作将资源移动至系统回收站；销毁操作必须经过二次确认且不可恢复。
- 云端存储源仅展示其连接器已声明支持的处置操作；不支持可恢复删除时，界面必须清楚说明风险。
- 用户可在设置中心初始化或调整系统资源根目录，并看到迁移影响说明。
- 用户可维护有限范围的系统监控目录；系统不得默认监控整台电脑。
- 用户可查看存储源支持的能力，并按资源类型设置默认查看程序或使用系统默认程序。
- 监听目录发现新资源时，系统将其放入资源收件箱并提供合并提醒，而不自动建立业务归属。
- 用户可在收件箱中为资源指定空间、资源集、资源类型，并选择仅关联、导入并托管、暂后处理或忽略。
- 收件箱对重复路径、临时文件、构建产物和敏感文件执行去重、过滤或保护性提示。

## 11. 迭代建议

### 第一阶段：资源管理最小闭环

空间、资源集、资源引用、本地文件系统浏览、资源分类、基础标签与筛选、资源收件箱与有限范围目录监听。

### 第二阶段：连接与关系

支持一个资源被多个资源集引用、资源集之间关联、Git 仓库信息读取，以及存储源连接器框架。

### 第三阶段：工作与智能能力

在管理层之上增加任务、需求、问题等可选对象；针对已授权资源建立索引、搜索和问答，并将回答链接回原始资源。

## 12. 待确认事项

- 一个资源是否需要在第一阶段支持同时归属多个资源集？
- “资源集模板”是否需要预置工作项目、产品、旅行等少量模板，还是完全自由命名？
- 本地资源移动后，是以路径更新为主，还是需要加入文件指纹以辅助重新定位？
- 后续优先接入 Git、某个云盘，还是对象存储？
