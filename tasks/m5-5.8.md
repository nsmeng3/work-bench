# 任务包 m5-5.8 · 合并通知与角标（前端）

## 目标

实现收件箱合并通知：当 `inbox_stats.pending` 计数增加时，在应用内右上角弹出合并通知（多条事件只提示一次），点击跳转收件箱；侧边栏角标实时更新。

## 需求与设计出处

- 详细设计说明书 §2.7 `inbox_stats`：「用于托盘/侧边栏角标；聚合通知由此驱动」
- 详细设计说明书 §4.3：「合并同窗口事件；生成一条或一组收件箱条目 → `inbox_stats` 计数变化；前端展示合并通知」
- 开发计划 M5-5.8 验收点：多条事件只提示一次

## 调用的接口（契约冻结）

- `inbox_stats`（轮询）

## 允许改动

- `app/src/hooks/useInboxStats.ts`（**新建**，轮询 hook）
- `app/src/components/InboxNotification.tsx`（**新建**，合并通知组件）
- `app/src/App.tsx`（集成 hook + 通知组件到全局布局）
- `app/src/api/inbox.ts`（追加 `inboxStats` 封装 + mock）
- `app/src/api/types.ts`（追加 InboxStats 类型）

**禁止改动**：
- `app/src-tauri/**`、`docs/**`、vite 端口

## 要求

1. **轮询 hook**（`useInboxStats`）：
   - 每 5 秒轮询 `inbox_stats`（与后端 5 秒聚合窗口对齐）
   - 返回 `{ pending, snoozed, lastEventAt, prevPending }`
   - 用 `useRef` 记录上一次 pending 计数，便于计算增量
2. **合并通知**（`InboxNotification`）：
   - 当 `pending > prevPending` 时弹出 antd `notification.info`
   - 文案：「收件箱新增 N 条待处理」（N = pending - prevPending）
   - 「前往查看」按钮跳 `/inbox`
   - 5 秒内多次增量只弹一次（用 debounce 或记录最后弹窗时间）
   - 应用启动时不弹（仅响应增量）
3. **角标**：
   - 侧边栏「收件箱」入口的 antd `Badge` 显示 `pending` 计数
   - 计数为 0 时隐藏 Badge
4. **样式**：Ant Design v5；沿用主题变量
5. **mock**：mock `inbox_stats` 支持手动触发增量（便于测试通知）
