# M7-4 任务包：内嵌终端

## 目标

终端不再散落在桌面，而是**长在项目里**：每个空间有自己的终端面板，cwd 自动是空间根目录，关闭面板即回收 PTY 进程。

## 验收标准（M7 §8）

- [ ] 空间详情页有"终端"tab（与"资源集"/"待办"并列）
- [ ] 终端 tab 内可开多个 shell 会话（标签栏 + 新建/关闭按钮）
- [ ] 新建会话的 cwd 自动是该空间的根目录（如果空间配置了 root 路径）；未配置则用 `~`
- [ ] 终端里可以正常跑命令、Ctrl+C、上下方向键翻历史、Cmd+K 清屏
- [ ] 关闭终端 tab / 切换到别的空间时，PTY 子进程被正确回收（`ps aux | grep -c "zsh.*<space>"` 不增）
- [ ] 关闭整个应用时，所有 PTY 子进程被回收

## 技术选型（已锁定）

- **前端**：`@xterm/xterm` + `@xterm/addon-fit` + `@xterm/addon-web-links`
- **后端**：`portable-pty = "0.8"` （crate）
- **通信**：Tauri Channel（流式输出用 Channel，不适合 invoke 一来一回）

## 后端设计

### 新模块 `app/src-tauri/src/terminal.rs`

```rust
/// 单个 PTY 会话
pub struct PtySession {
    pub id: String,
    pub space_id: Option<String>,
    pub cwd: PathBuf,
    pub shell: String,                  // 默认 $SHELL，fallback /bin/zsh
    writer: Box<dyn Write + Send>,      // 写入 stdin
    master: Box<dyn MasterPty + Send>,  // 用于 resize
    child: Box<dyn Child + Send + Sync>,
    reader_task: JoinHandle<()>,        // 读输出转发到 channel
}

/// 全局会话表
pub struct TerminalState {
    pub sessions: Arc<Mutex<HashMap<String, PtySession>>>,
}
```

### 命令清单

| 命令 | 入参 | 出参 | 说明 |
|---|---|---|---|
| `terminal_create` | `space_id?: string, cwd?: string, cols: u16, rows: u16` | `{ session_id: string }` | 创建 PTY，启动 reader task，通过 channel 推送输出 |
| `terminal_write` | `session_id: string, data: string` | `()` | 写入 stdin |
| `terminal_resize` | `session_id: string, cols: u16, rows: u16` | `()` | 调 master.resize |
| `terminal_close` | `session_id: string` | `()` | kill child + 移除会话 |
| `terminal_list` | `()` | `Vec<{session_id, space_id, cwd}>` | 列出活跃会话（调试用） |

### Channel 输出事件

```rust
// 前端订阅
Channel<TerminalEvent>

#[serde(tag = "kind", rename_all = "snake_case")]
pub enum TerminalEvent {
    Data { data: String },     // PTY stdout/stderr
    Exited { code: Option<i32> },
}
```

### 关键实现细节

1. **reader task**：`tokio::task::spawn_blocking` 循环 `reader.read()`，把字节送到 channel。因为 `portable-pty` 的 read 是阻塞的。
2. **退出清理**：`child.wait()` 在另一个 task，退出后自动从 sessions 表移除并推送 `Exited` 事件。
3. **应用退出清理**：在 `lib.rs` 的 `Builder::build` 之后，注册 `on_event` 监听 `RunEvent::ExitRequested`，遍历 sessions kill 所有 child。
4. **shell 选择**：`std::env::var("SHELL").unwrap_or("/bin/zsh".into())`
5. **cwd 解析**：`space_id` 提供时，从 space 表读 `root_path` 字段（M7 之前可能没有，需要查 schema；没有则退回 `dirs::home_dir()`）

### 单元测试

PTY 测试在 CI 不稳定，只做**最小化**测试：
- `terminal_create` 能创建会话并返回 id
- `terminal_write` + 读 channel 能拿到 `echo hello` 的输出
- `terminal_close` 后 `terminal_list` 不再包含该会话
- 重复 close 幂等不 panic

真实交互（Ctrl+C、颜色渲染等）手动验收。

## 前端设计

### 新组件 `components/TerminalPanel.tsx`

```
┌──────────────────────────────────────────┐
│ [终端 1] [终端 2] [+]      [空间名]      │  ← 标签栏
├──────────────────────────────────────────┤
│                                          │
│         xterm.js 画布                    │
│                                          │
└──────────────────────────────────────────┘
```

逻辑：
- 进入空间详情页"终端"tab → 自动创建第一个会话
- 点 [+] 新建会话
- 点标签上的 × 关闭会话（调 `terminal_close`）
- 切换 tab 时**不销毁**会话，只切 canvas 挂载（用 `display: none` 切换）
- 离开空间详情页时销毁所有该空间的会话

### xterm 初始化

```tsx
const term = new Terminal({
  fontFamily: 'Menlo, Monaco, "Courier New", monospace',
  fontSize: 13,
  cursorBlink: true,
  scrollback: 5000,
});
const fitAddon = new FitAddon();
term.loadAddon(fitAddon);
term.loadAddon(new WebLinksAddon());
term.open(containerRef.current);
fitAddon.fit();
```

### 事件订阅

```tsx
const channel = new Channel<TerminalEvent>();
channel.onmessage = (event) => {
  if (event.kind === "data") term.write(event.data);
  else if (event.kind === "exited") {
    term.write("\r\n[进程已退出]\r\n");
    // 从 tabs 移除
  }
};
await terminalCreate({ spaceId, cols, rows }, channel);
```

### 输入

```tsx
term.onData((data) => {
  void terminalWrite({ sessionId, data });
});
```

### resize

```tsx
term.onResize(({ cols, rows }) => {
  void terminalResize({ sessionId, cols, rows });
});
// 窗口尺寸变化时 fitAddon.fit() 会触发 onResize
```

## 边界（不做）

- ❌ 跨窗口拖出
- ❌ 分屏
- ❌ 会话持久化（关了就没了）
- ❌ SSH、tmux
- ❌ 全局悬浮终端（只长在空间里）
- ❌ 主题配置（用默认深色）

## 风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| `portable-pty` 在 macOS arm64 兼容性 | 高 | **先做个 5 分钟 spike**：起一个 `cargo run --example pty_test` 验证能 spawn zsh |
| xterm.js 与 antd 样式冲突 | 低 | CSS 隔离 + xterm 自带样式 |
| Channel 高频事件丢帧 | 中 | 后端用 `BufReader` + 批量 flush（每 16ms 或 8KB 一次） |
| PTY 泄漏 | 高 | Drop trait + 应用退出清理 + 单元测试验证 |
| Tauri 主线程阻塞 | 中 | 所有 PTY 操作都 spawn_blocking |
