# 任务包 m3-3.5 · 初始化向导界面（前端）

## 目标

实现首次启动初始化向导：检测 `settings_get_root_dir` 返回 `initialized=false` 时，强制引导用户选择/输入资源根目录，调用 `settings_init_root_dir` 建出 6 个子目录，成功后进入主界面。

## 需求与设计出处

- 详细设计说明书 §2.8 设置中心（`settings_get_root_dir` / `settings_init_root_dir` 契约，**冻结**）
- 详细设计说明书 §4「首次启动初始化资源根目录」
- 开发计划 M3-3.5 验收点：首启强制走初始化

## 调用的接口（契约冻结）

- `settings_get_root_dir()` → `{ rootDir?: string, initialized: bool }`
- `settings_init_root_dir { rootDir }` → `{ rootDir, created: string[] }`

**重要**：后端 3.4 可能尚未合并进 main。前端按契约实现真实 `invoke` 调用；若联调时后端不存在，在 `src/api/` 层做按契约返回假数据的 mock 开关（沿用 M2 的 `VITE_MOCK_API` 模式），默认关。mock 形状必须与契约逐字段一致。

## 允许改动

- `app/src/**`（页面、组件、api 封装、样式、路由）
- `app/package.json`（如需新增前端依赖，先在看板备注登记；优先用 antd 现成组件）

**禁止改动**：
- `app/src-tauri/**`（Rust 侧）
- `docs/**` 契约文档
- `app/vite.config.ts` 端口段

## 要求

1. **首启检测**：应用启动后先调 `settings_get_root_dir`；`initialized=false` 时路由强制跳 `/init`（或等效路径），主界面其它入口隐藏/禁用，直至初始化成功。
2. **向导步骤**（单页即可，无需多步）：
   - 说明文案：「选择资源根目录，将在其下创建 Code / Documents / Data / Artifacts / Tools / Media 6 个子目录」
   - 路径输入框 + 「浏览…」按钮（用 M2 已注册的 `@tauri-apps/plugin-dialog` 的 `open({ directory: true })`）
   - 「初始化」按钮：调 `settings_init_root_dir`，loading 态，成功后展示 `created` 列表（可折叠）
   - 失败按统一错误模型提示 `message`；`retryable=true` 给重试按钮
3. **二次进入**：已完成初始化后再次访问 `/init`，自动跳回主界面。
4. **UI 库**：Ant Design v5（M2 决策延续），用 `Form` / `Input` / `Button` / `Alert` / `Card` / `Typography`，不引入新 UI 框架。
5. **样式**：沿用 M1 骨架的主题变量，不写覆盖 antd 类名的 CSS。
6. **测试**：本阶段前端仍以 `pnpm build` 无头验收为准；界面效果由用户在 review 阶段人工点验。

## 验收命令

```bash
cd app && pnpm build
```

通过即完成。
