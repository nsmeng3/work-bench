# 任务包 m3-3.1 · 落地路径计算领域逻辑（后端·纯函数）

## 目标

实现 M3 落地子系统的纯函数领域层：**给定引用类型 + 资源根目录 + 源文件名，计算建议目标路径；检测目标冲突；给出冲突改名建议**。本任务只交付纯函数与单测，不接 Tauri 命令、不写库、不动文件系统。

落地路径计算是 3.2（`ref_create_managed` 两阶段）的前置依赖，必须先沉淀成可单测的纯函数，避免把规则散在命令实现里。

## 需求与设计出处

- 详细设计说明书 §2 `ref_create_managed` 出参 `ManagedPlan{ proposedTarget, conflicts, ... }`（**契约冻结**）
- 详细设计说明书 §4.1「导入并托管」流程：计算建议目标路径 → 检查冲突/大小/文件数
- 详细设计说明书 §5「领域规则（落地路径计算、忽略匹配、聚合窗口）为纯函数，单测覆盖」
- 开发计划 M3-3.1 验收点：纯函数单测覆盖
- 资源类型枚举：`code / document / data / artifact / tool / media`（见 `migrations/0001_init.sql:68`）

## 接口契约（本任务自定义内部 API，非 Tauri 命令）

在 `app/src-tauri/src/landing.rs`（新建）中提供：

```rust
/// 6 个类型 → 子目录名映射（与详细设计 §2 一致：类型首字母大写）
pub fn type_to_subdir(ref_type: &str) -> Result<&'static str, AppError>;
// code→Code, document→Documents, data→Data, artifact→Artifacts, tool→Tools, media→Media

/// 计算建议目标路径：{rootDir}/{TypeSubdir}/{sourceName}
pub fn propose_target(root_dir: &Path, ref_type: &str, source_name: &str) -> Result<PathBuf, AppError>;

/// 冲突改名建议：name → "name (2)" / "name (3)" ...；对带扩展名的文件，插入到主名后
/// 例：report.pdf → "report (2).pdf"；archive → "archive (2)"
pub fn suggest_rename(existing_name: &str, taken: &[&str]) -> String;
```

错误：未知类型 → `COMMON_INVALID_PARAM`。

## 允许改动

- `app/src-tauri/src/landing.rs`（**新建**，纯函数 + 单元测试 `#[cfg(test)] mod tests`）
- `app/src-tauri/src/lib.rs`（仅 `mod landing;` 一行注册，**不动** `generate_handler!` 宏内的命令注册）

**禁止改动**：
- `app/src-tauri/migrations/**`（M3 默认无 schema 变更）
- 其他已有 `*.rs`（reference/collection/query/fs_ops/error/db/space/tag 等）
- `app/src/**`（前端）
- `docs/**` 契约文档

## 要求

1. **纯函数**：不读写文件系统、不连接数据库、不调用 Tauri API；路径运算全用 `std::path::Path`。
2. **单元测试覆盖**：
   - 6 个类型各自映射到正确子目录名（大小写、复数形式按上表）
   - 未知类型返回 `COMMON_INVALID_PARAM`
   - `propose_target` 在 Unix 风格路径下产出 `{root}/{Subdir}/{name}`
   - `suggest_rename` 处理：无冲突 / 一重冲突 / 多重冲突 / 无扩展名 / 多段扩展名（`a.tar.gz` → `a (2).tar.gz` 或 `a.tar (2).gz` 任选并固化）/ 空 taken 列表
3. 不引入新第三方依赖（用 `std::path` 即可）；如确需，先在看板备注登记。
4. 不改 `error.rs`，直接复用现有 `AppError` / `COMMON_INVALID_PARAM` 封装。
