# 任务包 m2-2.3 · 引用服务（后端）

## 目标

实现资源引用的 4 个命令：`ref_create_external` / `ref_update` / `ref_get` / `ref_list`。（`ref_create_managed`、`ref_relocate`、`ref_check_health`、`ref_open`、`ref_reveal_in_finder` 属后续任务，不在本范围。）

## 需求与设计出处

- 详细设计说明书 §2.5（引用契约，**已冻结**）
- 详细设计说明书 §2.2（统一错误模型，复用已入库的 `AppError`）
- 开发计划 M2-2.3 验收点：仅关联创建绝不触碰文件（**有测试断言**）

## 接口契约（摘自 §2.5）

### `ref_create_external`（仅关联）
- 入参：`{ collectionId, name, type, locator: {kind:"path", path}, description?, tags?, lifecycle?, confidentiality?, indexed? }`
- `type ∈ code|document|data|artifact|tool|media`
- 出参：`Reference`
- **关键行为：只登记，绝不复制/移动原文件（§6.3）** —— 这是本任务的核心验收点
- 错误：`FS_PATH_NOT_FOUND`（路径不存在时）、`COMMON_INVALID_PARAM`

### `ref_update`
- 入参：`{ id, name?, description?, tags?, lifecycle?, confidentiality?, indexed? }`
- 只允许改管理属性；`type`/`locator`/`hosting` 不可改
- 错误：`COMMON_NOT_FOUND`、`COMMON_INVALID_PARAM`

### `ref_get { id }` → `Reference`（错误 `COMMON_NOT_FOUND`）
### `ref_list { collectionId, type?, lifecycle?, disposition? }` → `Reference[]`

## 要求

1. camelCase 序列化（与 space/collection 一致）；`locator_json` 在出参中反序列化为结构化 `locator` 对象。
2. `ref_create_external` 校验路径存在性（不存在 → `FS_PATH_NOT_FOUND`），但**绝不写文件系统**：必须有测试断言 —— 创建前后源文件的 mtime/内容不变，且不产生新文件。
3. tags 走 `reference_tag` 表，`ref_update` 传 tags 时为全量替换语义（与 collection 一致）。
4. `ref_list` 的三个过滤条件可组合；`disposition` 默认不含已删除。
5. 单测覆盖：4 命令正常路径 + 契约错误路径 + **"绝不触碰文件"专项断言**（用临时目录真实文件验证）。
