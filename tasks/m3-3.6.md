# 任务包 m3-3.6 · 导入并托管确认框（前端）

## 目标

实现「导入并托管」两阶段确认框：用户选定源文件/目录后，前端先调 `ref_create_managed(confirmed=false)` 拿到 `ManagedPlan`，在确认框中展示源→目标对比、冲突提示、copy/move 选择，用户确认后再调 `ref_create_managed(confirmed=true)` 执行落地。

## 需求与设计出处

- 详细设计说明书 §2 `ref_create_managed` 契约（**冻结**）
- 详细设计说明书 §4.1 流程图：plan → 确认 → confirmed
- 开发计划 M3-3.6 验收点：两阶段确认完整

## 调用的接口（契约冻结）

`ref_create_managed`，签名见详细设计 §2。

**入参关键字段**（在前端组装）：
- 基础字段：与 `ref_create_external` 相同（`spaceId / collectionId / type / name / description? / tags? / lifecycle? / confidentiality?` + `locator{ kind: "path", path }`）
- 托管专属：`managedAction: "copy" | "move"`、`targetName?: string`、`confirmed: bool`

**出参**：
- `confirmed=false` → `ManagedPlan{ kind:"managed_plan", source, proposedTarget, action, sizeBytes, fileCount, conflicts[] }`
- `confirmed=true` → `Reference`

**重要**：后端 3.2 可能尚未合并进 main。前端按契约实现真实 `invoke` 调用；若联调时后端不存在，在 `src/api/` 层做 mock 开关（沿用 `VITE_MOCK_API` 模式），mock 形状与契约逐字段一致。

## 要求

1. **入口**：在引用创建流程中新增「导入并托管」选项（与 M2 已交付的「仅关联（external）」并列）。具体入口位置可放在资源集详情页的引用创建按钮组，下拉选择「仅关联 / 导入并托管」。
2. **两阶段流程**：
   - **阶段一（plan）**：用户选好源路径后，前端调 `confirmed=false` 拿 `ManagedPlan`；loading 态
   - **确认框展示**：
     - 源路径（只读）
     - 目标路径（`proposedTarget`，只读展示）+ 「自定义目标名」输入框（填入后前端重新拼目标路径预览，**不再次调用 plan**）
     - `managedAction` 单选：`copy`（保留源）/ `move`（移动，源将被删除）；默认 `copy`
     - `sizeBytes` 与 `fileCount` 友好展示（人类可读单位；目录显示文件数）
     - `conflicts` 非空时醒目提示（黄色 Alert），列出每条冲突；此时「确认」按钮**禁用**直至用户改 `targetName` 使冲突消失（前端本地去重检查即可，无需再调 plan）
   - **阶段二（confirmed）**：调 `confirmed=true`；loading；成功后 message 提示并刷新引用列表
3. **错误处理**：`FS_TARGET_EXISTS` → 提示目标已存在，引导改名；`FS_PATH_NOT_FOUND` → 源已不在；`COMMON_IO` → 通用 IO 错误；其他按统一错误模型展示 `message`。
4. **取消**：任何阶段点取消都直接关闭，**不产生任何写操作**（确认框打开期间后端不应已写文件）。
5. **UI 库**：Ant Design v5；用 `Modal` / `Form` / `Radio.Group` / `Alert` / `Descriptions` / `Input`；样式沿用主题变量。
6. **复用**：与 M2-2.10 的「仅关联」创建表单共享空间/资源集/类型/标签等基础字段子组件（如已存在），不重复实现。

## 验收命令

```bash
cd app && pnpm build
```

通过即完成（界面与两阶段交互由用户在 review 阶段人工点验）。
