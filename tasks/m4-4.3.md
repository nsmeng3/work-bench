# 任务包 m4-4.3 · disp_preview（后端，可取消）

## 目标

实现 `disp_preview` Tauri 命令：删除/销毁确认框的专用数据接口 —— 返回目标路径、是否目录、文件数、总大小、能力、警告文案。**目录递归统计在后台线程执行，支持取消**。

## 需求与设计出处

- 详细设计说明书 §2.6 `disp_preview`（**契约冻结**）
- 详细设计说明书 §6 性能：「目录递归统计（disp_preview）在后台线程执行并支持取消」
- 开发计划 M4-4.3 验收点：大目录统计可取消

## 接口契约（摘自详细设计 §2.6，逐字段对齐）

**入参**：`{ refId: string }`

**出参**：
```json
{
  "target": "/abs/path",
  "isDir": true,
  "fileCount": 1234,
  "totalBytes": 5678901,
  "capability": { "archive": true, "softDelete": true, "destroy": true, "restoreFromBin": false, "reason": {} },
  "warning": "目录包含 1234 个文件；销毁后不可恢复"
}
```

**错误**：`COMMON_NOT_FOUND`（refId 不存在或对应文件已不在磁盘）

## 允许改动

- `app/src-tauri/src/disposition.rs`（追加 `disp_preview` 命令 + 后台统计 worker + 取消机制 + 单测）
- `app/src-tauri/src/lib.rs`（注册命令）

**禁止改动**：
- `app/src-tauri/migrations/**`
- `app/src-tauri/src/reference.rs`
- `app/src/**`、`docs/**`

## 要求

1. **后台线程**：用 `tokio::task::spawn_blocking` 把目录递归统计（walk + 累加）放到阻塞线程池，不阻塞 async runtime。
2. **可取消**：用 `tokio::sync::watch` 或 `Arc<AtomicBool>` 实现协作式取消。前端可通过新命令 `disp_preview_cancel { previewId }` 取消，或依赖 Tauri 的 IPC 断开时自动取消（二选一，固化为代码注释）。
3. **previewId**：每次 preview 调用生成 UUID 作为 previewId 返回，便于取消与日志关联。
4. **fileCount / totalBytes**：单文件直接读 metadata；目录递归 walk（不跟随符号链接出根，与 M3-3.2 一致）。
5. **capability**：调用 4.1 已交付的能力计算纯函数。
6. **warning**：按 fileCount / totalBytes 生成中文文案（目录含文件数 / 销毁后不可恢复 / 大小）
7. **单元测试**：
   - 单文件：fileCount=1、totalBytes=文件大小、isDir=false
   - 目录：多文件嵌套、符号链接不跟随、空目录
   - 大目录模拟（创建 1000 个空文件）：统计可在合理时间内完成
   - 取消：启动 preview 后立即 cancel，确认统计提前终止
   - refId 不存在 / 文件已被外部删除 → `COMMON_NOT_FOUND`
8. 不引入新第三方依赖（tokio / uuid 已有）。
