# 任务包 m2-2.9 · 资源集详情页（前端）

## 目标

资源集详情页：按类型分组展示引用（六类型分组），与 `collection_get` 出参对齐。

## 需求与设计出处

- 详细设计说明书 §2.4 `collection_get`（CollectionDetail.referencesByType 六分组 + health）
- 开发计划 M2-2.9 验收点：分组展示与 `collection_get` 对齐

## 调用的接口

`collection_get { id }` → `CollectionDetail`（后端已在 main 实现）。引用条目的操作按钮（编辑/健康检查等）属 2.10/2.11，本任务只读展示 + 每项显示 health 标记。

## 基线与约定

- main 已含：antd v5、`api/` 封装模式（types/errors/mock/space.ts/collection.ts）、AppShell、SpacePage→CollectionPage 下钻（state 切换）。**先读这些文件**再动手，沿用同一模式：新增 `api/reference.ts` 如需、详情页从 CollectionPage 下钻（继续 state 切换，不加 react-router）。
- **UI 库：Ant Design v5**。分组展示建议用 `Collapse` 或 `Tabs` 承载六类型分组（空分组可折叠/灰显），引用条目用 `Table` 或 `List`，health 用 `Badge`/`Tag` 三色（ok 绿 / missing 红 / unknown 灰）。
- mock 层同步加 `collection_get` 种子数据（覆盖六类型中有数据的 2~3 类 + 空类 + 三种 health 各至少一条），`VITE_MOCK_API` 开关模式与既有一致。

## 允许改动

- `app/src/**`

**禁止改动**：`app/src-tauri/**`、`app/package.json`（不加依赖）、`docs/**`。

## 要求

1. 详情页头部展示 Collection 元信息（名称、summary、tags、状态、创建时间）。
2. 六类型分组固定展示（键序：code/document/data/artifact/tool/media），每组标题带数量徽标。
3. 引用条目展示：名称、locator.path、lifecycle、confidentiality、health 标记、创建时间。
4. `CollectionDetail` 及 `Reference` 类型放 `api/types.ts`，时间字段 `number`（Unix 秒）。
5. 错误处理沿用统一错误结构 message + retryable 重试。
