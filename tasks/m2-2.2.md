# 任务包 m2-2.2 · 资源集服务（后端）

## 目标

实现资源集管理 5 命令 + `collection_get` 按类型聚合详情查询。

## 需求与设计出处

- 详细设计说明书 §2.4（资源集管理契约，**已冻结，逐字段遵守**）
- 详细设计说明书 §2.2（统一错误模型，复用 2.1 已实现的 `AppError`）
- 开发计划 M2-2.2 验收点：`collection_get` 返回分组结构

## 接口契约（摘自详细设计 §2.4）

| 命令 | 入参 | 出参 | 关键错误 |
| --- | --- | --- | --- |
| `collection_create` | `{ spaceId, name, summary?, tags?: string[] }` | `Collection` | `COMMON_NOT_FOUND`（空间不存在或已归档） |
| `collection_update` | `{ id, name?, summary?, tags? }` | `Collection` | `COMMON_NOT_FOUND` |
| `collection_archive` / `collection_restore` | `{ id }` | `Collection` | `COMMON_NOT_FOUND` 等 |
| `collection_get` | `{ id }` | `CollectionDetail`（含 `referencesByType` 六类型分组 + `health` 字段） | `COMMON_NOT_FOUND` |

`CollectionDetail.referencesByType` 的六类键：`code` / `document` / `data` / `artifact` / `tool` / `media`，每项 `{ ref, health }`，`health ∈ ok|missing|unknown`（本阶段引用表尚无任何写入方，分组返回空数组即可，但查询结构必须按契约实现并通过测试）。
