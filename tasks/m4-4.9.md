## 契约（已冻结）

### `ref_undo_import`

**入参**：
```json
{
  "refId": "uuid",
  "confirmed": false
}
```

**出参（两阶段）**：
- `confirmed=false` → `UndoPlan`：
  ```json
  {
    "refId": "uuid",
    "refName": "报告.pdf",
    "managedAction": "copy",
    "currentPath": "{root}/Documents/报告.pdf",
    "originalSource": "/abs/source/报告.pdf",
    "canUndo": true,
    "blockers": []
  }
  ```
- `confirmed=true` → `()`

**关键行为**：
1. **canUndo=false 的 blocker 场景**（前端禁用撤销按钮并提示原因）：
   - `hosting != 'managed'`（仅 managed 导入可撤销）
   - `locator_json.originalSource` 为 null（M3 期间创建的引用无此字段）
   - 目标文件已被外部修改/删除/移动（mtime 变化或不存在）
   - `managedAction == 'move'` 且原源路径已被其他文件占用
   - 引用创建时间超过 24h（`UNDO_WINDOW_SECS`）
2. **撤销动作**：
   - `copy` → 删除目标文件 + 删除引用记录
   - `move` → 把目标文件移回 `originalSource` + 删除引用记录（源路径已被占 → `FS_TARGET_EXISTS` 中止）
3. **审计**：写 `disposition_audit` action='undo_import'，note 记录 originalSource 与 managedAction
4. **互斥**：复用 `MANAGED_WRITE_LOCK`

**错误**：`COMMON_NOT_FOUND` / `COMMON_FORBIDDEN`（canUndo=false）/ `FS_PERMISSION_DENIED` / `COMMON_IO` / `FS_TARGET_EXISTS` / `COMMON_CONFIRM_REQUIRED`（confirmed != true）

**locator_json schema 扩展**（向后兼容）：
```json
{
  "kind": "path",
  "path": "/abs/current/path",
  "originalSource": "/abs/original/path"  // 新增，可选；M3 期间数据为 null
}
```

**配套改动**：
- M3-3.2 的 `ref_create_managed` 在写 `locator_json` 时**追加** `originalSource` 字段（值为用户提供的源路径）
- 这是对本任务外的既有命令的**增强**，需要同步改 `reference.rs` 的 create_managed 逻辑（属本任务范围）

## 要求

**后端**：
1. **locator_json 扩展**：M3 期间创建的引用没有 `originalSource`，其 `UndoPlan.canUndo=false` + blocker 说明「该引用创建时未记录原始源，无法撤销」
2. **两阶段**：plan 阶段不写文件不改库；confirmed 阶段执行
3. **blocker 检测**（plan 阶段）：
   - hosting != managed
   - originalSource 为 null
   - 目标文件不存在或 mtime 晚于导入时间 + 5s 容差（外部已修改）
   - move 且 originalSource 已被占
   - 创建时间 > 24h
4. **撤销执行**（confirmed 阶段）：
   - 拿 `MANAGED_WRITE_LOCK`
   - copy：删除目标文件（若存在）→ 删除引用行
   - move：先检查 originalSource 是否被占（被占则 FS_TARGET_EXISTS 中止，不做任何写）→ 移动文件 → 删除引用行
   - 写审计 action='undo_import'，note JSON `{"managedAction": "...", "originalSource": "..."}`
5. **create_managed 增强**：写 `locator_json` 时加 `originalSource` 字段；单测断言该字段存在且值正确
6. **单元测试**：
   - 老引用（无 originalSource）plan → canUndo=false + blocker
   - copy 撤销：目标删除 + 引用删除 + 审计正确
   - move 撤销：文件移回 + 引用删除 + 审计正确
   - move 撤销源被占 → FS_TARGET_EXISTS + 文件未动 + 引用未删
   - 超 24h 窗口 → canUndo=false
   - confirmed=false → UndoPlan；confirmed=true 执行
   - 并发：undo 与 create_managed 互斥
7. 不引入新第三方依赖。

**前端**：
1. 引用列表行操作加「撤销导入」按钮，仅当 `hosting=='managed'` 且 24h 内显示；点击调 plan → 确认框（显示 UndoPlan 信息 + blockers）→ confirmed 执行
2. blockers 非空时确认按钮禁用并列出原因
3. 成功 toast 提示「已撤销导入」+ 刷新列表
4. mock 数据覆盖：可撤销 / 超窗口 / 无 originalSource / move 源被占 四种场景
5. UI 库：Ant Design v5
