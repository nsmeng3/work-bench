# 任务包 m4-4.6 · disp_audit_list + 审计查看界面（全栈）

## 目标

后端实现 `disp_audit_list` 查询命令；前端实现审计查看界面（按引用 / 按操作类型 / 分页浏览处置历史）。

## 需求与设计出处

- 详细设计说明书 §2.6 `disp_audit_list`（**契约冻结**）
- 详细设计说明书 §3.2 `disposition_audit` schema（无外键，销毁后审计独立存活）
- 开发计划 M4-4.6 验收点：可查任意资源的处置历史

## 接口契约（摘自详细设计 §2.6，逐字段对齐）

**入参**：`{ refId?, action?, limit?, offset? }`（全部可选）
- `action`: `'archive' | 'unarchive' | 'soft_delete' | 'destroy'`
- `limit` 默认 50，最大 200；`offset` 默认 0

**出参**：`DispositionAudit[]`，字段对齐 `migrations/0001_init.sql:143` schema：
```json
[{
  "id": "uuid",
  "refId": "ref_uuid",
  "refName": "报告.pdf",
  "action": "destroy",
  "locatorSnapshot": { "kind": "path", "path": "/abs/path" },
  "actor": "local_user",
  "note": "...",
  "at": 1725000000
}]
```

**错误**：`COMMON_INVALID_PARAM`（action 非法 / limit 越界）

## 要求

**后端**：
1. SQL：`SELECT * FROM disposition_audit WHERE (refId = ? OR ? IS NULL) AND (action = ? OR ? IS NULL) ORDER BY at DESC LIMIT ? OFFSET ?`
2. 参数校验：action 不在 4 个合法值内 → `COMMON_INVALID_PARAM`；limit > 200 → 截断为 200（或报错，二选一固化）
3. 单元测试：空库 / 单条 / 多条分页 / refId 过滤 / action 过滤 / 组合过滤 / 时间倒序

**前端**：
1. 列表列：时间（人类可读）/ 引用名（refName 快照）/ 操作（action 中文映射 + 颜色：archive 蓝 / unarchive 绿 / soft_delete 黄 / destroy 红）/ 路径快照 / actor / note
2. 筛选：action 下拉（全部 / 归档 / 恢复 / 删除 / 销毁）+ refId 搜索（高级，可省略）
3. 分页：antd `Pagination`，pageSize 固定 50
4. mock：沿用 `VITE_MOCK_API` 模式，造 4 种 action 各几条假数据
5. UI 库：Ant Design v5 `Table` / `Select` / `Tag` / `Pagination`
6. 已销毁的引用：refName 显示快照文本（无链接）；未销毁的可点击跳到资源集详情页（如便于实现）
