# M7-1 任务包：资源打开/操作

## 目标

资源"只能看不能用" → 让资源在 UI 上真正可以打开/操作。后端 `ref_open` 与 `ref_reveal_in_finder` 已实现且注册（见 `app/src-tauri/src/lib.rs:138-139`），但前端零调用。本任务纯前端接入 + 少量后端可能要补。

## 验收标准（M7 §8）

- [ ] 资源列表/详情能"打开"，走 `ref_open` 三级策略
- [ ] 资源右键菜单有"访达中显示 / 复制路径 / 用其他程序打开"
- [ ] 打开动作会写入 `ref_access_log`（为 M7-3 Dashboard 的"最近资源"供数据）—— **本任务只做埋点调用，不消费**

## 范围

### 前端

1. **`app/src/api/commands.ts`**：新增封装
   - `refOpen(refId: string, appOverride?: string)` → 调 `ref_open`
   - `refRevealInFinder(refId: string)` → 调 `ref_reveal_in_finder`
   - `refCopyPath(refId: string)` → 前端直接 `navigator.clipboard.writeText(path)`，无需后端
   - `refOpenWith(refId: string, appPath: string)` → 等价 `refOpen` 带 override

2. **`CollectionDetailPage.tsx`**（资源列表主战场）：
   - 每行加主按钮"打开"
   - 右键菜单：打开 / 访达中显示 / 复制路径 / 用其他程序打开…
   - 双击 = 打开

3. **`InboxDetailPanel.tsx`** 与资源详情相关面板：
   - 顶部操作条：打开 / 定位 / 复制路径

4. **埋点**：每次成功调用 `refOpen` / `refRevealInFinder` / `refCopyPath` 后调后端 `ref_log_access(ref_id, action)`（见下方"后端要补"）。

### 后端要补（只一个命令）

```rust
#[tauri::command]
async fn ref_log_access(ref_id: String, action: String) -> Result<(), ApiError>
```

写入 `ref_access_log` 表（表结构见 §7 数据迁移）。

### 数据迁移

新增 `app/src-tauri/migrations/0006_ref_access_log.sql`：

```sql
CREATE TABLE IF NOT EXISTS ref_access_log (
    id        TEXT PRIMARY KEY,
    ref_id    TEXT NOT NULL REFERENCES resource_reference(id) ON DELETE CASCADE,
    action    TEXT CHECK (action IN ('open','reveal','copy_path','open_with')) NOT NULL,
    at        INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_ref_access_at ON ref_access_log(at DESC);
CREATE INDEX IF NOT EXISTS idx_ref_access_ref ON ref_access_log(ref_id);
```

**注意**：M7 设计大纲里我把这个表放在 `0007_`，现挪到 `0006_`，因为 M7-1 就要写它。todo 表则顺延为 `0007_todo.sql`。

## 风险

| 风险 | 等级 | 应对 |
|---|---|---|
| `ref_open` 三级策略在某些文件类型失效 | 中 | 手动验收：文本/图片/文件夹/链接各试一次 |
| `ref_access_log` 写入失败影响主流程 | 低 | 埋点调用 `await` 但捕获错误只 `console.warn` |
| macOS `open -R` 行为在非访达应用下的兼容 | 低 | 后端已经处理，前端只是接入 |
