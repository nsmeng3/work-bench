# 任务包 m2-2.7 · 空间列表 + 创建/编辑对话框（前端）

## 目标

实现空间管理界面：左侧导航下"空间"页，含空间列表、创建对话框、编辑对话框、归档/恢复操作。

## 需求与设计出处

- 需求说明书：空间相关章节
- 详细设计说明书 §2.3（`space_*` 5 命令契约，前端调用入参/出参以此为准）
- 详细设计说明书 §2.2（统一错误结构 `{code, message, details, retryable}`，前端据此提示）
- 开发计划 M2-2.7 验收点：可建/改/归档空间

## 调用的接口（契约冻结）

`space_create` / `space_update` / `space_archive` / `space_restore` / `space_list`，签名见详细设计 §2.3。

**重要**：后端 2.1 可能尚未合并进 main。前端按契约实现真实 `invoke` 调用；若联调时后端不存在，在 `src/api/` 层做一个按契约返回假数据的 mock 开关（如 `import.meta.env.VITE_MOCK_API`），默认关。mock 数据形状必须与契约逐字段一致。

## 允许改动

- `app/src/**`（页面、组件、api 封装、样式）
- `app/package.json`（如需新增前端依赖，先在看板备注登记）

**禁止改动**：`app/src-tauri/**`（Rust 侧）、`app/vite.config.ts` 端口段、`docs/**`。

## 要求

1. 列表默认显示 active 空间，可切换查看 archived。
2. 创建/编辑共用一个对话框组件；名称必填、超长提示（对齐后端 `COMMON_INVALID_PARAM` 行为）。
3. 归档需二次确认（轻量确认即可，区别于 M4 销毁的输入全名确认）。
4. 已归档空间不可编辑，UI 上禁用编辑入口（对齐 `COMMON_CONFLICT`）。
5. 命令失败时展示统一错误结构中的 `message`，`retryable=true` 时给重试按钮。
6. 样式沿用 M1 骨架的主题变量，不引入新的 UI 框架（如需引入先登记）。

## 验收命令

```bash
cd app && pnpm build
```

通过即完成（本阶段无头验收以构建为准；界面效果由用户在 review 阶段人工点验）。
