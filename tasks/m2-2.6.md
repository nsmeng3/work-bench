# 任务包 m2-2.6 · 健康检查 / 打开 / 访达定位（后端）

## 目标

实现 `ref_check_health` / `ref_open` / `ref_reveal_in_finder` 三个命令（契约 §2.5，已冻结）。

## 接口契约（摘自 §2.5）

### `ref_check_health`
- 入参：`{ id }` 或 `{ collectionId }`（二选一）
- 出参：`[{ refId, health, detail? }]`，`health ∈ ok|missing|unknown`
- 只检测不修改数据；路径存在 → ok，不存在 → missing

### `ref_open`
- 入参：`{ id, appOverride?: "/Applications/xxx.app" }`
- 出参：`{ opened: true, strategy: "system_default"|"custom" }`
- 按默认程序打开；appOverride 为本次覆盖。本阶段默认程序设置尚未实现（M6），统一按 system_default 打开（macOS `open`，Windows `explorer`，Linux `xdg-open`）；appOverride 给定则用该程序打开并返回 `custom`。
- 错误：`FS_PATH_NOT_FOUND`、`FS_PERMISSION_DENIED`

### `ref_reveal_in_finder`
- 入参：`{ id }`
- 在系统文件管理器中显示（macOS `open -R`，Windows `explorer /select,`，Linux 退化为打开所在目录）
- 错误：`FS_PATH_NOT_FOUND`

## 基线

main 已含 reference.rs（`ref_get` 可查 locator）。复用其查询逻辑或自行按 id 查 `resource_reference`。

## 允许改动

- `app/src-tauri/src/fs_ops.rs`（新建）、`app/src-tauri/src/lib.rs`（仅注册命令）

**禁止改动**：space/collection/reference/error/db.rs、migrations、`app/src/**`、契约文档。

## 要求

1. camelCase 序列化；复用 `AppError`。
2. 健康检查只读文件系统元数据（`std::fs::metadata`），不打开文件内容。
3. `ref_open`/`ref_reveal_in_finder` 起子进程用 `std::process::Command`，路径作为独立 argv 元素传递，**绝不拼接 shell 字符串**（防注入）。
4. 单测：`ref_check_health` 三种健康度 + 两种入参模式 + 批量 collectionId 模式（用 tempfile 造存在/不存在路径）；`ref_open`/`reveal` 只测路径不存在时的错误分支（真实打开行为无法在无头测试断言）。
5. 跨平台分支用 `#[cfg(target_os = ...)]`，当前开发/验收在 macOS，保证 macOS 路径正确，其他平台编译通过即可。
