# 任务包 m4-4.5 · disp_destroy（后端，销毁 + 审计 + 引用删除）

## 目标

实现 `disp_destroy` Tauri 命令：永久删除引用对应的文件/目录，写审计（保留），**物理删除引用行**。

## 需求与设计出处

- 详细设计说明书 §2.6 `disp_destroy`（**契约冻结**）
- 详细设计说明书 §4.2 销毁流程（三档处置中最严）
- 详细设计说明书 §6.7 / §3.2 `disposition_audit` 无外键约束（销毁后引用行已删，审计独立存活）
- 详细设计说明书 §5 并发：「多步写操作（托管落地、根目录迁移、销毁）通过互斥锁串行化」
- 开发计划 M4-4.5 验收点：销毁后审计仍在、引用已删

## 接口契约（摘自详细设计 §2.6，逐字段对齐）

**入参**：`{ refId, confirmText: string, confirmed: true }`

**出参**：`()`（无 Reference，因为引用行已被物理删除）— 或返回 `{ deletedRefId }`，实现时二选一并固化注释。

**关键行为**：
1. `confirmText` 必须与资源当前 `name` **完全一致**，否则 `COMMON_CONFIRM_REQUIRED`
2. 对目录先统计（前端须先调 `disp_preview` 向用户展示；本命令直接执行）
3. 永久删除（**不经回收站**，用 `tokio::fs::remove_file` / `remove_dir_all`）
4. 写审计（action='destroy'，**审计保留**）
5. **物理删除引用行**（`DELETE FROM resource_reference WHERE id = ?`）

**错误**：`COMMON_CONFIRM_REQUIRED` / `FS_PERMISSION_DENIED` / `COMMON_IO` / `COMMON_NOT_FOUND` / `COMMON_FORBIDDEN`（destroy 能力 false，罕见）

## 允许改动

- `app/src-tauri/src/disposition.rs`（追加命令 + 销毁 worker + 单测）
- `app/src-tauri/src/lib.rs`（注册命令）

**禁止改动**：
- `app/src-tauri/migrations/**`
- `app/src-tauri/src/reference.rs`（删除用 raw sqlx 即可，不改既有函数）
- `app/src/**`、`docs/**`

## 要求

1. **互斥**：复用 M3-3.2 已交付的 `MANAGED_WRITE_LOCK: OnceLock<Mutex<()>>`（详细设计 §5 要求托管落地/根目录迁移/销毁共用互斥）。若该常量在 `reference.rs` 是私有的，把它改为 `pub(crate)` 并在 `disposition.rs` 引用；或在 `disposition.rs` 新建 `DESTROY_LOCK` 并通过注释说明与 MANAGED_WRITE_LOCK 的关系（二选一，固化注释）。
2. **confirmText 校验**：从 DB 读出当前 ref.name，**逐字符比对**；不匹配立即返回 `COMMON_CONFIRM_REQUIRED`，**不做任何写操作**。
3. **顺序**：先删文件（`tokio::fs`），成功后开事务写审计 + DELETE 引用行。文件删除失败不写库；写库失败补偿：尝试把已删文件的路径记录下来（best-effort 日志，**不**尝试恢复文件 —— 永久删除无法回滚）。
4. **审计字段**：
   - `id`：UUID
   - `ref_id` / `ref_name`：当前引用 id 与 name 快照
   - `action`：`'destroy'`
   - `locator_snapshot`：当前 `locator_json` 完整快照（含被删路径）
   - `actor`：`'local_user'`
   - `note`：可填 fileCount/totalBytes 摘要（从 4.3 preview 复用或重新统计）
   - `at`：Unix 秒
5. **单元测试**：
   - confirmText 不匹配 → `COMMON_CONFIRM_REQUIRED`，文件未动、库未动
   - confirmed=false → `COMMON_CONFIRM_REQUIRED`
   - 单文件销毁：文件消失 + 引用行删除 + 审计记录正确
   - 目录销毁（含嵌套）：目录整棵消失 + 引用行删除 + 审计记录正确
   - 已删除（disposition=deleted）的引用再销毁：按能力规则允许或拒绝，固化为注释
   - 不存在 refId → `COMMON_NOT_FOUND`
   - 销毁后通过 `disp_audit_list`（4.6 实现，可先用 raw SQL 验证）能查到审计记录
6. 不引入新第三方依赖。
