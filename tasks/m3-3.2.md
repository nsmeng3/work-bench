# 任务包 m3-3.2 · `ref_create_managed` 两阶段命令（后端）

## 目标

实现详细设计 §2 的 `ref_create_managed` Tauri 命令，两阶段语义：

- `confirmed=false`：仅返回 `ManagedPlan`，**不执行任何写操作**（不写文件、不写库）。
- `confirmed=true`：执行复制/移动到目标路径，在事务中创建引用记录；失败时补偿删除已落地文件，保证「要么都成功要么都没有」。

## 需求与设计出处

- 详细设计说明书 §2 `ref_create_managed` 契约（**冻结，逐字段遵守**）
- 详细设计说明书 §4.1 流程图 + 异常处理要点（补偿删除、错误码语义）
- 详细设计说明书 §5「多步写操作通过互斥锁串行化」（**本任务须落地互斥**）
- 开发计划 M3-3.2 验收点：失败补偿删除、事务落库

## 接口契约（摘自详细设计 §2，逐字段对齐）

**入参**：在 `ref_create_external` 基础上额外加：
```json
{
  "managedAction": "copy" | "move",
  "targetName?": "自定义目标名（缺省用源名）",
  "confirmed": false
}
```

**出参（两阶段）**：
- `confirmed=false` → `ManagedPlan{ kind:"managed_plan", source, proposedTarget, action, sizeBytes, fileCount, conflicts[] }`
- `confirmed=true` → `Reference`（结构同 `ref_create_external` 返回）

**错误**：`FS_PATH_NOT_FOUND` / `FS_TARGET_EXISTS` / `FS_PERMISSION_DENIED` / `COMMON_IO` / `COMMON_CONFIRM_REQUIRED` / `COMMON_INVALID_PARAM` / `COMMON_DB`

**关键语义**：
- `confirmed=false` 时如果检测到目标冲突，通过 `conflicts: ["目标已存在同名项"]` 返回，**不**直接报错；`confirmed=true` 且目标已存在才返回 `FS_TARGET_EXISTS`。
- `targetName` 为空字符串或仅空白 → `COMMON_INVALID_PARAM`。
- 复制/移动成功但写库失败 → 补偿删除已落地目标，返回 `COMMON_DB`。

- `app/src-tauri/src/landing.rs`（如需扩展 `propose_target` 调用方式，可追加函数；**不改** 3.1 已交付的既有函数签名）

**禁止改动**：
- `app/src-tauri/migrations/**`（schema 已含 `hosting`/`locator_json`，无需变更）
- `app/src/**`（前端）
- 契约文档 `docs/**`

## 要求

1. **互斥**：使用 `tokio::sync::Mutex`（或 `std::sync::Mutex`，与既有异步风格一致）包裹「落地 + 写库」复合操作，串行化多步写。互斥锁放置在 `AppState` 或 `static OnceLock`（参考既有状态管理模式）。
2. **大小/文件数统计**：单文件直接读 metadata；目录递归 walk（注意符号链接不要跟随出根，避免越界）。
3. **冲突检测**：plan 阶段检查目标路径是否已存在；confirmed 阶段落地前再检一次（防 TOCTOU）。
4. **复制 vs 移动**：`action=copy` 保留源；`action=move` 复制完成后删除源（删除失败回滚：删目标、报 `COMMON_IO`）。
5. **事务落库**：`sqlx::Transaction` 内完成 INSERT reference；任何一步失败 rollback + 补偿删目标。
6. **引用记录**：`hosting='managed'`，`locator_json` 填落地后的绝对路径（遵守现有 locator schema），`type/collectionId/spaceId/...` 沿用 `ref_create_external` 的校验逻辑（可抽公共函数复用）。
7. **单元测试**：
   - plan 阶段：源不存在 / 源是单文件 / 源是目录 / 目标已存在 / 自定义 targetName / targetName 空白
   - confirmed 阶段：copy 成功 / move 成功 / 目标已存在报错 / 权限失败（用只读目录模拟，若跨平台难模拟则跳过）/ 写库失败补偿删目标（用内存 db 强制触发 constraint 错误）
   - 互斥：并发两个 confirmed 调用，验证串行执行（可用计数器或耗时断言）
8. 不引入新第三方依赖；`tokio::fs` / `sqlx` / 既有 `fs_ops` 工具即可。如确需 `walkdir` 等，先在看板备注登记。
