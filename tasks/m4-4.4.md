# 任务包 m4-4.4 · disp_soft_delete（后端，trash crate 接入）

## 目标

实现 `disp_soft_delete` Tauri 命令：把引用对应的文件/目录移入系统回收站，`disposition` 置为 `deleted`，写审计。

## 需求与设计出处

- 详细设计说明书 §2.6 `disp_soft_delete`（**契约冻结**）
- 详细设计说明书 §5.1 系统回收站（Rust `trash` crate，跨平台）
- 开发计划 M4-4.4 验收点：文件进系统回收站

## 接口契约（摘自详细设计 §2.6，逐字段对齐）

**入参**：`{ refId, confirmed: true }`

**出参**：`Reference`（`disposition='deleted'`）

**关键行为**：
1. 检查 `softDelete` 能力（调用 4.1 的能力计算），不支持则 `COMMON_FORBIDDEN`
2. 对目录：先统计文件数与总大小返回给前端展示（前端在确认前调 `disp_preview`，本命令直接执行不再重新统计）
3. 执行系统回收站移动（`trash::delete`）
4. 写审计（action='soft_delete'）

**错误**：`FS_RECYCLE_UNSUPPORTED` / `FS_PERMISSION_DENIED` / `COMMON_IO` / `COMMON_NOT_FOUND` / `COMMON_FORBIDDEN` / `COMMON_CONFIRM_REQUIRED`（confirmed != true）

## 允许改动

- `app/src-tauri/src/disposition.rs`（追加命令 + 单测）
- `app/src-tauri/src/lib.rs`（注册命令）
- `app/src-tauri/Cargo.toml`（**新增 `trash` crate**，版本看板备注登记）

**禁止改动**：
- `app/src-tauri/migrations/**`
- `app/src/**`、`docs/**`

## 要求

1. **依赖登记**：在 `Cargo.toml` 加 `trash = "5"`（或当前稳定版，版本号写注释）。**先在看板备注登记，再由编排者统一在 main 安装** —— 本任务在 worktree 内 `cargo add trash` 后提交 Cargo.toml + Cargo.lock 变更。
2. **能力预检**：执行 `trash::delete` 前先调用 4.1 的能力计算；`softDelete=false` 直接返回 `COMMON_FORBIDDEN`（不尝试移动）。
3. **confirmed 强制**：`confirmed != true` 返回 `COMMON_CONFIRM_REQUIRED`。
4. **事务**：UPDATE disposition + INSERT audit 在同一事务中完成；**trash::delete 先执行，成功后才开事务写库**（与 M3-3.2 相反顺序 —— 落地先，写库后，失败则无残留）。
5. **文件系统失败补偿**：trash::delete 成功但写库失败时，**不回滚回收站**（文件已在回收站，用户可手动恢复）；返回 `COMMON_DB` 并在审计表尝试写一条 action='soft_delete' + note='db_failed' 的记录（best-effort）。
6. **单元测试**：
   - confirmed=false → `COMMON_CONFIRM_REQUIRED`
   - softDelete 能力 false → `COMMON_FORBIDDEN`
   - 不存在 refId → `COMMON_NOT_FOUND`
   - 文件已被外部删除 → `COMMON_NOT_FOUND`（或 `FS_PATH_NOT_FOUND`，二选一固化）
   - 成功路径：临时文件 → trash::delete → 文件不在原位置 + disposition=deleted + 审计记录正确
   - **注意 CI/测试环境**：`trash::delete` 在某些 Linux 无回收站环境会失败，测试用 `#[cfg(target_os = "macos")]` 或 feature-gate 标记平台相关测试；跨平台 CI 失败时用 `#[ignore]` + 注释说明
7. 不改 4.1 / 4.2 / 4.3 已交付的函数签名。
