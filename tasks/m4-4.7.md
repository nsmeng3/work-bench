# 任务包 m4-4.7 · 三档操作按钮 + 确认对话框（前端）

## 目标

在引用列表 / 资源集详情页加「归档 / 恢复 / 删除 / 销毁」三档操作按钮，按 4.1 能力渲染可用态；打开对应确认对话框；销毁对话框要求用户**输入资源全名**才能点确认。

## 需求与设计出处

- 详细设计说明书 §2.6 处置命令契约（**冻结**）
- 详细设计说明书 §4.2 销毁流程
- 开发计划 M4-4.7 验收点：三档视觉与确认等级区分清晰

## 调用的接口（契约冻结）

- `disp_get_capabilities` / `disp_archive` / `disp_unarchive` / `disp_soft_delete` / `disp_destroy` / `disp_preview`

**重要**：后端 4.1-4.5 可能尚未合并进 main。前端按契约实现真实 `invoke` 调用；若联调时后端不存在，在 `src/api/` 层做 mock 开关（沿用 `VITE_MOCK_API` 模式），mock 形状与契约逐字段一致。

## 要求

1. **按钮组视觉分级**（antd v5）：
   - 归档 / 恢复：`Button type="default"`，蓝色系
   - 删除（回收站）：`Button danger`，黄色预警
   - 销毁：`Button type="primary" danger`，红色高危
   - 按 `disp_get_capabilities` 返回的可用性 `disabled`，不可用项 tooltip 显示 `reason`
2. **确认对话框**：
   - **归档**：轻量确认（`Modal.confirm`），文案「归档后不再出现在主列表，可随时恢复」
   - **删除**：`Modal` + `disp_preview` 数据展示（文件数 / 大小 / 目标路径），文案「文件将移入系统回收站」
   - **销毁**：`Modal` + `disp_preview` 数据 + **输入框要求输入资源完整名称**，不一致时确认按钮禁用；文案「**此操作不可恢复**，请输入完整名称确认」
3. **预览加载**：打开删除/销毁对话框时立即调 `disp_preview`，loading 态；大目录统计期间显示 spinner 与当前已统计计数（如便于）
4. **成功反馈**：对应操作成功后 `message.success` + 刷新引用列表
5. **错误处理**：`COMMON_CONFIRM_REQUIRED` → 提示「名称不匹配」；`FS_RECYCLE_UNSUPPORTED` → 「当前系统不支持回收站，只能归档或销毁」；其他按统一错误模型
6. **mock**：4 种引用状态（none / archived / deleted / 大目录）各造 1-2 条，覆盖三档按钮可用/禁用/确认流程
