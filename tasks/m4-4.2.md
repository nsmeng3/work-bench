# 任务包 m4-4.2 · disp_archive / disp_unarchive（后端）

## 目标

实现 `disp_archive` 与 `disp_unarchive` 两个 Tauri 命令：仅改 `disposition` 字段，**不触碰文件系统**。

## 需求与设计出处

- 详细设计说明书 §2.6 `disp_archive` / `disp_unarchive`（**契约冻结**）
- 详细设计说明书 §6.7：「归档仅改 disposition，不动文件」
- 开发计划 M4-4.2 验收点：仅改 disposition 不动文件

## 接口契约（摘自详细设计 §2.6，逐字段对齐）

| 命令 | 入参 | 出参 | 错误 |
| --- | --- | --- | --- |
| `disp_archive` | `{ refId }` | `Reference` | `COMMON_NOT_FOUND` / `COMMON_CONFLICT`（已归档） |
| `disp_unarchive` | `{ refId }` | `Reference` | `COMMON_NOT_FOUND` / `COMMON_CONFLICT`（未归档） |

**关键语义**：
- `disp_archive`：`disposition` 从 `none` → `archived`；已 archived 时报 `COMMON_CONFLICT`；已 deleted 时报 `COMMON_CONFLICT`（回收站中的不能归档）
- `disp_unarchive`：`disposition` 从 `archived` → `none`；未归档时报 `COMMON_CONFLICT`
- **审计**：两条命令都要写 `disposition_audit`（action='archive' / 'unarchive'）
- **不动文件**：文件系统完全不变

## 允许改动

- `app/src-tauri/src/disposition.rs`（追加 2 个命令 + 审计写入辅助 + 单测；**不改** 4.1 已交付的 `disp_get_capabilities` 行为）
- `app/src-tauri/src/lib.rs`（`generate_handler!` 宏追加 2 个命令）

**禁止改动**：
- `app/src-tauri/migrations/**`
- `app/src-tauri/src/reference.rs`（引用查询复用现有 `ref_get` 逻辑，不改签名）
- `app/src/**`、`docs/**`

## 要求

1. **审计写入**：参考 `migrations/0001_init.sql:143` 的 `disposition_audit` schema（id / ref_id / ref_name / action / locator_snapshot / actor / note / at）。`actor` 固定 `'local_user'`，`note` 可空，`locator_snapshot` 存当前 `locator_json` 完整快照。
2. **事务**：UPDATE disposition + INSERT audit 在同一 sqlx 事务中完成。
3. **单元测试**：
   - 归档：none → archived 成功，返回的 Reference.disposition 正确
   - 重复归档 → `COMMON_CONFLICT`
   - 已删除时归档 → `COMMON_CONFLICT`
   - 恢复：archived → none 成功
   - 未归档时恢复 → `COMMON_CONFLICT`
   - 归档后查审计表：1 条 archive 记录，ref_name / locator_snapshot 快照正确
   - 恢复后再归档：审计表共 3 条记录（archive + unarchive + archive）
   - 不存在 refId → `COMMON_NOT_FOUND`
4. 不引入新依赖。
