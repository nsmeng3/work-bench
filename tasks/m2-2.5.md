# 任务包 m2-2.5 · 筛选服务（后端）

## 目标

实现 `query_refs` / `query_facets` 两个查询命令（契约 §2.9，已冻结）。

## 接口契约（摘自 §2.9）

### `query_refs`
- 入参（全可选）：`{ spaceId?, collectionId?, type?, tags?: string[], lifecycle?, confidentiality?, disposition?, sourceId?, keyword?, limit?, offset? }`
- 出参：`{ total: number, items: Reference[] }`
- 第一阶段仅元数据筛选，不做内容检索

### `query_facets`
- 入参：`{ spaceId? }`
- 出参：各类型的可用筛选值与计数（用于侧边栏）—— 返回结构自定但需含 type/lifecycle/confidentiality/tags 四个维度的 value+count 列表，camelCase

## 基线

main 已含 space/collection/reference 全部实现（见 `src/reference.rs` 的 `list` 动态 WHERE 拼接，可参考但注意它只按 collectionId 过滤）。tags 在 `reference_tag` 表；空间过滤需经 `collection.space_id` JOIN。

## 允许改动

- `app/src-tauri/src/query.rs`（新建）、`app/src-tauri/src/lib.rs`（仅注册命令）

**禁止改动**：space/collection/reference/error/db.rs、migrations、`app/src/**`、契约文档。

## 要求

1. camelCase 序列化；`Reference` 出参结构与 reference.rs 的既有结构**完全一致**（含 locator 结构化、tags 数组）——可直接复用其行→结构转换逻辑（如为私有则在 query.rs 内重写等价转换，不修改 reference.rs）。
2. tags 筛选为 AND 语义（含全部给定标签）。
3. `keyword` 匹配 `name`/`description` 的 LIKE 模糊（转义 `%`/`_`）。
4. `limit`/`offset` 分页：`total` 为不受分页影响的计数；默认 limit 50、上限 200。
5. 结果确定性排序：`created_at DESC, id ASC`。
6. 单测：全字段单条件 + 多条件组合 + tags AND + keyword + 分页 total/items 一致性 + 边界（limit 超上限截断）。
