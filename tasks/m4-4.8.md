# 任务包 m4-4.8 · settings_change_root_dir（后端，修改根目录）

## 目标

实现 `settings_change_root_dir` Tauri 命令：修改资源根目录，支持 `future_only`（仅未来生效）与 `migrate`（迁移已有内容）两种策略，两阶段确认。

**来源**：M3 门禁期间用户建议（`tasks/m3-gate-log.md` backlog #1），详细设计 §2.8 / §4.4 契约已冻结但 M3 未实现。

## 需求与设计出处

- 详细设计说明书 §2.8 `settings_change_root_dir`（**契约冻结**）
- 详细设计说明书 §4.4 修改资源根目录流程（含迁移模式互斥约束）
- 详细设计说明书 §6.8：「绝不静默搬迁」

## 接口契约（摘自详细设计 §2.8，逐字段对齐）

**入参**：`{ newRootDir, strategy: "future_only" | "migrate", confirmed: false }`

**出参（两阶段）**：
- `confirmed=false` → `MigrationPlan { newRootDir, strategy, items: [{ refId, currentPath, proposedPath, status }], totalBytes, conflicts: [] }`
- `confirmed=true` 且 `strategy="migrate"` → `MigrationResult { migrated: [...], failed: [...] }`
- `confirmed=true` 且 `strategy="future_only"` → `{ newRootDir }`（直接更新 settings，无需 MigrationPlan）

**错误**：`FS_PERMISSION_DENIED` / `COMMON_IO` / `COMMON_INVALID_PARAM` / `COMMON_CONFIRM_REQUIRED`

**关键约束**：
- **迁移模式**：迁移过程中应用进入「迁移模式」，禁止新的托管落地与处置操作（详细设计 §4.4）—— 复用 M3-3.2 的 `MANAGED_WRITE_LOCK` 互斥
- **绝不静默搬迁**：`confirmed=false` 只返回 Plan，不做任何写操作
- `future_only`：只改 settings 表的 `root_dir`，不动已有文件（已有 managed 引用仍指向旧路径，可后续手动迁移）
- `migrate`：逐项复制到 `newRootDir/{TypeSubdir}/{原文件名}`，更新对应 `locator_json`；失败项记录到 `failed` 并继续下一项

## 允许改动

- `app/src-tauri/src/settings.rs`（追加 `settings_change_root_dir` 命令 + 迁移 worker + 单测；不改 3.4 已交付的 get/init 命令）
- `app/src-tauri/src/landing.rs`（可复用 `type_to_subdir` 拼目标路径；**不改**函数签名）
- `app/src-tauri/src/lib.rs`（注册命令）

**禁止改动**：
- `app/src-tauri/migrations/**`
- `app/src-tauri/src/reference.rs`（locator 更新用 raw sqlx）
- `app/src/**`、`docs/**`

## 要求

1. **future_only**：
   - 校验 newRootDir 非空 / 绝对路径 / 存在或可创建
   - 更新 settings 表 `root_dir`
   - 若新目录下 6 个子目录不存在则建出（复用 3.4 的初始化逻辑）
   - **不动**任何已有文件与引用记录
2. **migrate · plan 阶段**：
   - 扫描 `references` 表所有 `hosting='managed'` 的引用
   - 对每项计算 `proposedPath = {newRootDir}/{TypeSubdir}/{原文件名}`
   - 检查目标冲突 / 源是否仍存在
   - 返回 MigrationPlan（不写任何文件 / 不改库）
3. **migrate · confirmed 阶段**：
   - 拿 `MANAGED_WRITE_LOCK` 互斥锁（注释标注「与 M3-3.2 托管落地、M4-4.5 销毁共用」）
   - 逐项：复制 → 更新 `locator_json` → 写审计（action='migrate'，**这是对 disposition_audit.action 集合的扩展，需在代码注释中说明并在契约文档外标注**；若担心契约冻结，可退而求其次不写审计只记日志）
   - 单项失败：记录到 `failed`，继续下一项（不中断整批）
   - 全部完成后更新 settings 表 `root_dir`
4. **单元测试**：
   - newRootDir 空 / 相对路径 / 含 `..` → `COMMON_INVALID_PARAM`
   - future_only：settings 更新 + 6 子目录建出 + 已有引用 locator 不变
   - migrate plan：返回 items 数量与 managed 引用数一致；conflicts 检测正确
   - migrate confirmed：文件复制 + locator 更新 + settings 更新
   - 部分失败：某项源已被外部删除 → failed 含该项，其他项继续
   - 互斥：并发触发 migrate 与 create_managed，验证串行
5. 不引入新第三方依赖。
