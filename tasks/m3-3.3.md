# 任务包 m3-3.3 · 大文件复制进度事件（后端）

## 目标

在 3.2 已交付的 `ref_create_managed` 复制/移动执行路径上，加入**流式复制 + 周期进度事件发射**：`managed_progress{ refId, bytes, total }`，前端可据此渲染进度条。

## 需求与设计出处

- 详细设计说明书 §4.1 异常处理要点：「大文件复制：后端流式复制并周期发进度事件 `managed_progress{refId, bytes, total}`」（**契约冻结**）
- 开发计划 M3-3.3 验收点：前端能收到进度回调

## 接口契约（事件载荷，Tauri `emit` 到前端）

事件名：`managed_progress`

```json
{
  "refId": "<前端在 plan 阶段生成或后端在 confirmed 早期生成的临时 id>",
  "bytes": 1234567,
  "total": 9876543
}
```

- 频率：每复制满 1 MiB 或每 200ms 发一次（取先到者；具体阈值在实现中固化为常量并写注释）。
- 完成时：发最后一次 `bytes == total`（或省略，由 confirmed 命令返回代表完成 —— 二选一，需在代码注释中固化约定）。
- 失败时：不单独发事件，由 confirmed 命令的错误返回负责通知前端。

## 允许改动

- `app/src-tauri/src/reference.rs`（在 `create_managed` 内部接入进度 callback）
- `app/src-tauri/src/fs_ops.rs`（把 3.2 的复制函数改造为流式 + callback 注入；**保持**对外的函数签名兼容或做清晰的新增）
- `app/src-tauri/src/lib.rs`（如需注册事件相关辅助，按需追加；不动既有命令列表）

**禁止改动**：
- `app/src-tauri/migrations/**`
- `app/src/**`（前端；本任务只交付后端发射能力，前端监听在 3.7 做）
- 契约文档

## 要求

1. **流式复制**：用 `tokio::io::copy_buf` 或 `tokio::fs::File` + 缓冲循环，禁止一次性 `fs::read` 全量加载（避免大文件 OOM）。
2. **目录复制**：递归处理时，对每个文件单独累加进度，总 `total` 在 plan 阶段已算好并透传。
3. **refId 来源**：plan 阶段不生成 refId（无写库）；confirmed 阶段在事务开始前生成 UUID，事件载荷带它，便于前端区分并发任务。
4. **节流**：用常量 `PROGRESS_BYTE_STEP: u64 = 1 << 20` 与 `PROGRESS_TIME_STEP: Duration = Duration::from_millis(200)`，命名清晰，便于后续调优。
5. **单元测试**：
   - 小文件（< 1 MiB）复制：事件次数 ≤ 2（起点 + 终点）或不发（按你固化的约定断言）
   - 大文件（用 `tempfile` 造 3 MiB 假数据）：至少收到 2 次事件，最后一次 `bytes == total`
   - 事件载荷字段齐全（refId/bytes/total）
   - 失败路径：源文件中途被删，确认不发出 `bytes == total` 的完成事件
6. 不引入新依赖；用 Tauri 自带 `Emitter` API。
