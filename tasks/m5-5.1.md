# 任务包 m5-5.1 · 目录监听组件（后端，notify 接入）

## 目标

实现目录监听基础设施：用 `notify` crate 接入 macOS FSEvents / Windows ReadDirectoryChangesW / Linux inotify，把平台事件标准化为 `created/modified/renamed/removed` 四种，供 5.2/5.3 上层消费。

## 需求与设计出处

- 详细设计说明书 §5.2 目录监听（**契约冻结**）
- 开发计划 M5-5.1 验收点：监听目录新建文件能收到事件

## 接口契约（内部 API，非 Tauri 命令）

在 `app/src-tauri/src/watch.rs`（新建）中提供：

```rust
/// 标准化事件类型（§5.2 冻结）
pub enum WatchEventKind { Created, Modified, Renamed, Removed }

/// 标准化事件载荷
pub struct WatchEvent {
    pub kind: WatchEventKind,
    pub path: PathBuf,
    pub watch_dir_id: String,  // 来自 watch_dir 表
    pub at: i64,               // Unix 秒
}

/// 启动监听器：读 watch_dir 表，为每个 active 目录建 watcher；
/// 事件通过 tokio::sync::mpsc::Sender<WatchEvent> 发出。
pub async fn start_watchers(
    pool: SqlitePool,
    tx: mpsc::Sender<WatchEvent>,
) -> CmdResult<WatcherHandle>;

/// 停止所有监听器（应用退出时调用）
pub async fn stop_watchers(handle: WatcherHandle) -> CmdResult<()>;

/// 增量订阅/退订（settings_add_watch_dir / remove_watch_dir 时调用，5.4 接入）
pub async fn add_watch(handle: &WatcherHandle, watch_dir_id: String, path: PathBuf, recursive: bool) -> CmdResult<()>;
pub async fn remove_watch(handle: &WatcherHandle, watch_dir_id: &str) -> CmdResult<()>;
```

**事件标准化规则**（§5.2 冻结）：
- `notify::EventKind::Create` → `Created`
- `notify::EventKind::Modify` → `Modified`
- `notify::EventKind::Remove` → `Removed`
- `notify::EventKind::Rename`（both from/to）→ `Renamed`（from 路径）

## 允许改动

- `app/src-tauri/src/watch.rs`（**新建**，监听器 + 事件标准化 + 单测）
- `app/src-tauri/src/lib.rs`（`mod watch;` + 在 setup 钩子中启动 watcher）
- `app/src-tauri/Cargo.toml`（**新增 `notify` crate**，版本看板备注登记）

**禁止改动**：
- `app/src-tauri/migrations/**`（watch_dir 表 M1 已建）
- `app/src-tauri/src/*.rs` 其他既有文件
- `app/src/**`、`docs/**`

## 要求

1. **依赖登记**：在 `Cargo.toml` 加 `notify = "6"` 或当前稳定版（版本号写注释）。`cargo add notify` 后提交 Cargo.toml + Cargo.lock 变更。
2. **平台适配**：macOS 用 FSEvents（默认）、Windows 用 ReadDirectoryChangesW、Linux 用 inotify；notify crate 自动选。
3. **recursive 读取**：从 `watch_dir` 表读 `recursive` 字段决定用 `RecursiveMode::Recursive` 还是 `NonRecursive`。
4. **错误处理**：单个 watcher 启动失败不影响其他；记录日志并把对应 `watch_dir.paused = 1`（详细设计 §5.2 故障处理）。
5. **单元测试**：
   - 事件标准化映射正确（mock notify 事件验证 enum 转换）
   - 在 tempdir 上启动 watcher → 创建文件 → 收到 Created 事件
   - 修改文件 → 收到 Modified 事件
   - 删除文件 → 收到 Removed 事件
   - 停止 watcher 后不再收到事件
   - **平台相关测试**：用 `#[cfg(target_os = "macos")]` 或 `#[ignore]` 标注（CI 可能无 GUI 会话）
6. 不引入除 `notify` 外的新依赖。
