# 任务包 m5-5.4 · 收件箱服务 7 命令（后端）

## 目标

实现详细设计 §2.7 的收件箱 7 个 Tauri 命令：`inbox_list` / `inbox_get` / `inbox_assign` / `inbox_snooze` / `inbox_ignore` / `inbox_dismiss_stale` / `inbox_stats`。

## 需求与设计出处

- 详细设计说明书 §2.7 收件箱（**契约冻结**）
- 详细设计说明书 §4.3 收件箱流程
- 开发计划 M5-5.4 验收点：`inbox_assign` 四种模式可用

## 接口契约（摘自详细设计 §2.7，逐字段对齐）

| 命令 | 入参 | 出参 | 关键错误 |
| --- | --- | --- | --- |
| `inbox_list` | `{ status?, limit?, offset? }` | `InboxItem[]` | — |
| `inbox_get` | `{ id }` | `InboxItemDetail`（含可选预览） | `COMMON_NOT_FOUND` |
| `inbox_assign` | `{ id, mode, spaceId, collectionId, type, managedAction?, confirmed }` | `{ inboxItem, reference?, managedPlan? }` | `INBOX_STALE` / `COMMON_NOT_FOUND` / `COMMON_INVALID_PARAM` |
| `inbox_snooze` | `{ id, note?, remindAt? }` | `InboxItem` | `COMMON_NOT_FOUND` |
| `inbox_ignore` | `{ id, rule? }` | `InboxItem` | `COMMON_NOT_FOUND` |
| `inbox_dismiss_stale` | `{ id }` | `()` | `COMMON_NOT_FOUND` |
| `inbox_stats` | `()` | `{ pending, snoozed, lastEventAt }` | — |

**关键语义**：
- `inbox_assign mode='external'`：调 `ref_create_external` 创建引用，文件不动；成功后 inbox_item.status='processed'
- `inbox_assign mode='managed'`：调 `ref_create_managed` 走 M3 两阶段；`confirmed=false` 返回 `managedPlan`，`confirmed=true` 执行
- `inbox_assign` 处理时源文件已不存在 → `INBOX_STALE`，前端引导 `inbox_dismiss_stale`
- `inbox_ignore rule` 非 once 时写入 `ignore_rule` 表并触发 5.2 规则重载
- `inbox_stats` 返回 pending/snoozed 计数 + 最新事件时间（驱动前端合并通知）

## 允许改动

- `app/src-tauri/src/inbox.rs`（**新建**，7 个命令 + 单测）
- `app/src-tauri/src/lib.rs`（注册命令）
- `app/src-tauri/src/ignore.rs`（可追加规则重载入口；**不改** 5.2 核心逻辑）

**禁止改动**：
- `app/src-tauri/migrations/**`（inbox_item / ignore_rule 表 M1 已建）
- `app/src-tauri/src/reference.rs`（调用 `create_external` / `create_managed` 既有函数，不改签名）
- `app/src/**`、`docs/**`

## 要求

1. **InboxItem 结构**：对齐 `migrations/0001_init.sql:120` schema；camelCase 序列化。
2. **inbox_assign 集成**：
   - 调 `reference::create_external` / `create_managed` 既有业务函数
   - 成功后更新 inbox_item.status='processed' + processed_at
   - 事务：创建引用 + 更新 inbox_item 在同一 sqlx 事务
3. **inbox_ignore 规则**：`rule.kind != "once"` 时 INSERT ignore_rule 并调用 5.2 的 `load_rules` 重载入口（用 `Arc<RwLock>` 共享的规则集）
4. **inbox_stats**：`SELECT COUNT(*) WHERE status='pending'` / `'snoozed'` + `SELECT MAX(discovered_at)`
5. **单元测试**：
   - inbox_list 空库 / 单条 / 分页 / status 过滤
   - inbox_get 存在 / 不存在
   - inbox_assign external：成功创建引用 + inbox_item 状态变 processed
   - inbox_assign managed confirmed=false：返回 managedPlan
   - inbox_assign managed confirmed=true：执行托管 + inbox_item 状态变 processed
   - inbox_assign 源文件已删 → `INBOX_STALE`
   - inbox_snooze：更新 note/remindAt + status='snoozed'
   - inbox_ignore rule='once'：仅更新 status='ignored'，不写规则
   - inbox_ignore rule='by_ext'：写 ignore_rule + status='ignored'
   - inbox_dismiss_stale：更新 status='processed'
   - inbox_stats：pending/snoozed 计数 + lastEventAt
6. 不引入新第三方依赖。
