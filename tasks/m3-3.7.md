# 任务包 m3-3.7 · 大文件进度条与结果反馈（前端）

## 目标

在 3.6 交付的「导入并托管」确认框之上，叠加**大文件复制进度展示**：监听后端 `managed_progress` 事件，实时渲染进度条；完成/失败时给出明确结果反馈。

## 需求与设计出处

- 详细设计说明书 §4.1 异常处理要点：「大文件复制：后端流式复制并周期发进度事件 `managed_progress{refId, bytes, total}`，前端展示进度条」（**契约冻结**）
- 开发计划 M3-3.7 验收点：大文件有进度

## 监听的事件（契约冻结）

事件名：`managed_progress`

载荷：
```json
{ "refId": "...", "bytes": 1234567, "total": 9876543 }
```

后端节流约定（3.3 任务包）：每复制满 1 MiB 或每 200ms 发一次；完成时发最后一次 `bytes == total`（或省略由 confirmed 命令返回代表完成 —— 以 3.3 代码注释为准，前端两种都要兼容）。

## 允许改动

- `app/src/**`（组件、hooks、api 封装、事件订阅）
- `app/package.json`（新依赖先登记；优先 `@tauri-apps/api/event` 现成能力）

**禁止改动**：
- `app/src-tauri/**`
- `docs/**`

## 要求

1. **事件订阅**：用 `@tauri-apps/api/event` 的 `listen<ManagedProgressPayload>("managed_progress", ...)`；组件卸载时 `unlisten`。
2. **多任务区分**：用 `refId` 作为 key 维护进度 map（`Record<refId, { bytes, total }>`），同一时刻多个托管任务各自独立显示。
3. **UI 呈现**：
   - 在 3.6 确认框的 confirmed loading 阶段，将原 spinner 替换/增强为 `Progress` 组件（antd v5）
   - 显示百分比 + 已复制/总大小（人类可读单位，如「12.3 MB / 45.6 MB」）
   - `total === 0`（空文件/空目录）时显示 indeterminate 态
4. **完成反馈**：
   - 成功：`message.success("已导入并托管到 {targetPath}")`，关闭确认框，刷新引用列表
   - 失败：按错误码展示；进度条变红（`status="exception"`）短暂停留后关闭或留在确认框（二选一，在代码注释中固化）
5. **取消期间**：若用户在 confirmed 进行中点取消，前端**不真正中断后端复制**（后端无取消机制），仅在 UI 上隐藏进度；后台继续完成。在代码注释中标注此为已知限制，避免误以为支持取消。
6. **UI 库**：Ant Design v5；`Progress` / `message` / `Modal`；样式沿用主题变量。
7. **测试**：以 `pnpm build` 无头验收为准；进度条真实效果由用户在 review 阶段用一个大文件（建议 > 10 MB）人工点验。

## 验收命令

```bash
cd app && pnpm build
```

通过即完成。

## 交接说明

- M3 门禁会走一遍完整「导入并托管」流程，本任务交付的进度体验是门禁必经路径。
- M4 处置三档（软删/销毁）也会涉及大文件操作，可复用本任务沉淀的 `useManagedProgress` hook（如已抽象）。
