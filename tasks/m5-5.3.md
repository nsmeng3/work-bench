# 任务包 m5-5.3 · 聚合窗口缓冲 + 去重（后端）

## 目标

实现聚合窗口：消费 5.2 过滤后的 `WatchEvent` 流，按 5 秒窗口缓冲合并，同路径去重，路径已被正式引用/已有未处理条目的丢弃，最终生成 `inbox_item` 记录。

## 需求与设计出处

- 详细设计说明书 §5.2「5 秒聚合窗口 + 同路径去重 + 忽略规则前置过滤」
- 详细设计说明书 §4.3 收件箱流程（事件流图）
- 详细设计说明书 §6 性能：「聚合窗口为纯函数，单测覆盖」
- 开发计划 M5-5.3 验收点：短时间多事件合并为一条

## 接口契约（内部 API，非 Tauri 命令）

在 `app/src-tauri/src/aggregate.rs`（新建）中提供：

```rust
/// 聚合窗口常量（§5.2 冻结）
pub const AGGREGATE_WINDOW_SECS: i64 = 5;

/// 缓冲事件批次
pub struct EventBatch {
    pub window_start: i64,
    pub window_end: i64,
    pub events: Vec<WatchEvent>,
}

/// 聚合策略（纯函数）：
/// - 同路径去重：同窗口内同一路径的多事件合并为一条（取最新 kind + mtime）
/// - 路径已被正式引用（resource_reference.locator_json.path 匹配）→ 丢弃
/// - 同一路径已有未处理 inbox_item（status='pending'）→ 更新 mtime/event_kind，不新建
/// - 否则 → 新建 inbox_item
pub async fn aggregate_batch(
    pool: &SqlitePool,
    batch: EventBatch,
) -> CmdResult<AggregateResult>;

pub struct AggregateResult {
    pub created: usize,   // 新建 inbox_item 数
    pub updated: usize,   // 更新已有 inbox_item 数
    pub dropped: usize,   // 丢弃数（已引用 / 重复）
}

/// 在 WatchEvent 流上应用聚合窗口（5.2 接入点）
pub fn start_aggregator(
    pool: SqlitePool,
    rx: mpsc::Receiver<WatchEvent>,
) -> JoinHandle<()>;
```

## 要求

1. **窗口触发**：定时器每 5 秒触发一次 `aggregate_batch`；窗口内累积的事件作为一个批次处理。
2. **同路径去重**：用 `HashMap<PathBuf, WatchEvent>` 按路径 dedup，取最新事件（比较 `at` 字段）。
3. **已引用检查**：查询 `resource_reference.locator_json` JSON 提取 `$.path` 匹配当前事件路径（可用 `json_extract` SQL 或反序列化后比对）。
4. **未处理条目检查**：查询 `inbox_item WHERE path = ? AND status = 'pending'`；存在则 `UPDATE mtime/event_kind`，不新建。
5. **单元测试**：
   - 空批次 → 全 0
   - 同窗口同路径 3 事件 → 1 条 inbox_item（created=1）
   - 同窗口不同路径 3 事件 → 3 条 inbox_item（created=3）
   - 路径已被正式引用 → dropped=1
   - 路径已有 pending inbox_item → updated=1，created=0
   - 窗口常量 = 5 秒
6. 不引入新第三方依赖。
